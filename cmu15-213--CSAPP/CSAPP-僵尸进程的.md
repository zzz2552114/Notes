会。子进程 `exit(0)` 后，如果父进程还活着且没有调用 `wait()/waitpid()` 回收它，子进程就会进入 **僵尸状态**，在 `ps` 中通常显示为 `Z` 或 `Z+`。

原因是：子进程退出时，内核会释放它的大部分资源，如内存、文件描述符等，但会保留一部分信息：PID、退出状态、统计信息、进程表项等，等待父进程读取。父进程调用 `wait/waitpid` 后，这些残留信息才被释放。

例外：如果父进程显式把 `SIGCHLD` 设为 `SIG_IGN`，或设置 `SA_NOCLDWAIT`，Linux 下子进程退出后可由内核自动回收，不产生僵尸。默认的 `SIGCHLD` 忽略语义通常不等于自动回收。

### 对 CPU 的影响

僵尸进程本身：

- 不占用 CPU 时间；
- 不会被调度器调度；
- 不执行任何用户代码或内核代码；
- 不参与运行队列；
- 不会导致 CPU 使用率升高。

它主要占用的是内核资源：

- 进程表项；
- PID；
- 退出状态等少量信息。

所以单个僵尸对 CPU 基本没有直接影响。但如果父进程不断 `fork` 子进程且从不回收，僵尸会大量累积，最终可能耗尽 PID 或进程表项，导致 `fork()` 失败。这是间接影响，不是僵尸在消耗 CPU。

### 对 control flow 的影响

僵尸进程自身没有控制流。它已经终止，不会再执行指令，也不会被调度，因此：

- 不会抢占 CPU；
- 不会改变父进程或其他进程的指令流；
- 不会进入调度器；
- 不会产生系统调用或异常。

父进程的控制流会继续正常执行。唯一相关的控制流影响来自：

1. **SIGCHLD 信号**  
   子进程退出时，内核会向父进程发送 `SIGCHLD`。默认通常忽略，不改变控制流。但如果父进程捕获了 `SIGCHLD`，信号处理函数会异步插入父进程的控制流。

2. **父进程以后调用 `wait/waitpid`**  
   如果父进程之后调用 `wait/waitpid`，内核会发现僵尸子进程并立即回收它，`wait` 返回子进程 PID 和退出状态，父进程继续执行。

3. **资源耗尽后的间接影响**  
   如果僵尸太多导致 PID 耗尽，父进程再 `fork()` 会失败，父进程需要处理错误，这可能间接改变控制流。

4. **父进程退出后**  
   如果父进程一直不回收，但后来父进程自己退出了，僵尸子进程会被 `init` 或 `systemd` 收养并回收，最终消失。

总结：  
子进程会变成僵尸；僵尸不消耗 CPU，也不产生自己的控制流；它占用 PID/进程表项等内核资源。对父进程控制流的直接影响通常没有，除非涉及 `SIGCHLD` 信号处理、后续 `wait` 回收，或僵尸累积导致 `fork` 失败。避免办法是父进程调用 `wait/waitpid`，或显式忽略 `SIGCHLD` / 设置 `SA_NOCLDWAIT`。
