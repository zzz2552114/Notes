**1. 父进程先 exit，子进程还在：会变成孤儿进程**
- 子进程不会因为父进程退出而自动死掉。
- 内核会把它的父进程改为 `init`，传统上是 PID 1，所以 `PPID` 变成 1。
- Linux 还有 `subreaper` 机制：如果某个祖先进程设置了 `PR_SET_CHILD_SUBREAPER`，孤儿会被最近的 subreaper 收养，而不是 PID 1。
- 容器里 PID 1 可能不是传统 init，而是你的应用，所以“被 init 接管”实际是被容器里的 PID 1 接管。

**2. 对 CPU 的影响**
- 孤儿进程本身**继续正常参与调度**，该消耗多少 CPU 就消耗多少 CPU。
- 被 init 收养**不会增加 CPU 开销**，也不会降低它的 CPU 使用。
- 它不是僵尸，所以它可能正在运行、睡眠、阻塞 I/O 等。
- 如果它是一个 CPU 忙循环进程，它仍然会占 CPU。
- 真正不占 CPU 的是僵尸进程；孤儿进程不是僵尸。

**3. 等子进程 exit 后，init 会自动释放它吗？**
- 子进程退出后会先变成僵尸，并向收养者，通常是 init，发送 `SIGCHLD`。
- 收养者必须调用 `wait()` 或 `waitpid()` 才能回收它。
- 传统 `init`、`systemd` 这类 PID 1 会专门 `wait` 子进程，所以会**自动回收**，不会长期留僵尸。
- 但如果收养者不处理 `SIGCHLD`、不调用 `wait`，比如某些容器里不负责回收的 PID 1，那么子进程退出后仍会变成僵尸，直到收养者主动回收或收养者自己退出。

补充：父进程退出时，如果它之前已经有僵尸子进程，这些僵尸也会被 init 接管并回收。

总结：父进程先退，子进程变孤儿，被 PID 1 或 subreaper 收养，继续正常跑，正常耗 CPU；子进程退出后，传统 init/systemd 会 wait 回收，但收养者不 wait 的话仍会留僵尸。
