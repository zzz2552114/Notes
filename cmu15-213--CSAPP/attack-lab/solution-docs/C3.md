## C3 记录

**解决步骤**<br>
1. 阅读 [Writeup说明书](../attacklab-writeup.zh.md)，搞清楚 C3 的目标
2. 反汇编 `(gdb) disassemble getbuf`，详细见 [C1记录](../C1.md)。找到 ***%rsp*** 与 ***return地址*** 的相对距离，***还需要找到 %rsp 的绝对地址***
3. 反汇编 `(gdb) disassemble touch3`，找到 `touch3` 函数首行地址
4. 构建 ***传参程序*** 并且转化为字节形式

5. **串联好上面的一切**。用 `./hex2raw` 和 ***管道符*** 向`ctarget`传入答案

***下面来看一下手册里的 touch3 C代码***
```c
int hexmatch(unsigned val, char *sval)
{
    char cbuf[110];
    /* 让检查字符串的位置不可预测 */
    char *s = cbuf + random() % 100;
    // 下面的 sprintf函数是把 无符号整数 val 写成 8 位 16 进制字符串
    // 例如 val = 255，s = "000000ff"
    sprintf(s, "%.8x", val);
    // 下面是比较字符数组和刚才的字符串的前 9 位，逐字节读取字符数组的字节，ascii码比较
    return strncmp(sval, s, 9) == 0;
}

void touch3(char *sval)
{
    vlevel = 3;    
    // 注意下面的传参
    if (hexmatch(cookie, sval)) {
        printf("Touch3!: You called touch3(\"%s\")\n", sval);
        validate(3);
    } else {
        printf("Misfire: You called touch3(\"%s\")\n", sval);
        fail(3);
    }
    exit(0);
}
```
---
### 我们来想一下比较重要的一点，在执行完 getbuf 并 ret 之后，%rsp 指针停留在 %rsp + 48 处，后续执行 touch3 和 hexmatch 的时候会再次向下扩展并覆盖原有内容。<br>
***而我们又注意到在 `hexmatch` 函数里，sval 是字符数组首指针表示的，说明在比较的时候还是要去读取内存的。那我们应该放在哪里呢？***<br>
> 答案是放在不会被覆盖的上游函数 `test()` 的栈空间内部

***但是这个题也告诉我们，如果仅仅是空间占用，因为后续在 `touch2` 里直接 `exit(0)` 了，不会再次用到这块内容，所以不会导致错误***

---
### 因此我们的思路就很清晰了
```x86asm
// 注意这是放在 getbuf 开头的，跳转到这里的时候 getbuf 函数已经 ret 了，%rsp位置要注意一下
mov %rsp,%rdi
push $0x4018fa
ret
```
```sh
gcc -c c3-mov.s
objdump -d c3-mov.o

3:   68 fa 18 40 00          push   $0x4018fa

```
