在 POSIX 系统（如 Linux/Unix）中，`fork()` 之后，父进程和子进程的内存关系默认是：

**逻辑上相互独立，物理上采用“写时复制”（Copy-On-Write, COW）。**

也就是说：

- **不是完全共享**：子进程修改普通变量，父进程看不到，反之亦然。
- **也不是 fork 时立刻全部拷贝**：内核先让父子进程共享同一份物理内存页，但把这些页标记为只读。
- **当任一方尝试写某页时**，触发缺页异常，内核才为该进程复制这一页。之后该页就独立了。
- **没被写的页继续共享物理内存**，所以 `fork()` 通常很高效。

可以理解为：

| 内存类型              | fork 后行为                                      |
| --------------------- | ------------------------------------------------ |
| 代码段、只读数据      | 通常一直共享                                     |
| 全局/静态变量、堆、栈 | 写时复制，写后独立                               |
| 显式共享内存          | 需要 `mmap(MAP_SHARED)`、`shmget` 等，才真正共享 |
| 文件描述符            | 描述符表复制，但指向同一个打开文件，文件偏移共享 |

示例：

```c
#include <stdio.h>
#include <unistd.h>
#include <sys/wait.h>

int g = 1;

int main() {
    int x = 1;
    pid_t pid = fork();

    if (pid == 0) {
        g = 2;
        x = 2;
        printf("child: g=%d x=%d\n", g, x);
    } else {
        wait(NULL);
        printf("parent: g=%d x=%d\n", g, x);
    }
    return 0;
}
```

输出类似：

```text
child: g=2 x=2
parent: g=1 x=1
```

说明子进程修改 `g` 和 `x` 后，父进程看不到，父子进程的普通内存是独立的。

特殊情况：

- `vfork()`：子进程暂时共享父进程地址空间，直到 `exec` 或 `_exit`，很危险，一般不推荐。
- `clone(CLONE_VM, ...)`：可以共享地址空间，类似线程。
- 多线程：同一进程内的线程共享地址空间。

所以结论是：**默认 `fork()` 后，父子进程地址空间独立；物理内存是写时复制。想共享必须显式使用共享内存。**





同一进程下的不同线程：

- **不共享寄存器**
- **不固定在同一个 CPU 上**

具体说：

### 1. 寄存器不共享
寄存器是 **CPU 核心的硬件资源**，不是进程/线程之间的共享内存。

每个线程都有自己独立的**寄存器上下文**，包括：

- 程序计数器 PC
- 栈指针 SP
- 通用寄存器
- 状态寄存器/标志寄存器
- 等

线程运行时，内核把它的寄存器上下文加载到某个 CPU 核心的寄存器里；线程被切换走时，再把寄存器值保存回内存。下次再运行，再恢复。

所以逻辑上，**每个线程有自己的寄存器状态**，只是物理上轮流使用 CPU 的寄存器。

### 2. 不一定在同一个 CPU 上
线程是操作系统调度的基本单位。它可能：

- 在**同一个 CPU 核心**上分时运行：同一时刻只有一个线程跑，轮流使用同一组寄存器。
- 在**不同 CPU 核心**上并行运行：多个线程同时跑，各自使用各自核心的寄存器。
- 被调度器在不同时间迁移到不同核心。

除非你显式设置 CPU 亲和性，否则线程和某个 CPU 没有绑定关系。

### 3. 线程真正共享什么？
同一进程的线程共享：

- 地址空间：代码段、数据段、堆
- 全局变量、静态变量
- 打开的文件描述符
- 信号处理方式
- 当前工作目录等

每个线程独享：

- 寄存器上下文
- 栈
- 线程局部存储 TLS
- `errno`
- 信号屏蔽字等

### 总结
同一进程下的不同线程：

- **寄存器**：不共享，各自有独立的寄存器上下文。
- **CPU**：不固定，可能同核交替运行，也可能多核并行运行。
- 它们共享的是进程的内存空间和资源，不是 CPU 寄存器。





是的，**线程之间也会发生上下文切换**，而且机制和进程切换**很类似**，但通常**更轻量**。

### 相同点
线程和进程一样，都是被操作系统调度的对象。当 CPU 从一个线程切换到另一个线程时，内核需要：

- 保存当前线程的寄存器上下文：PC、SP、通用寄存器、标志寄存器等
- 保存线程的栈指针、线程局部存储、`errno`、信号屏蔽字等
- 选择下一个要运行的线程
- 恢复下一个线程的寄存器上下文
- 切换到它的栈和内核栈

所以从“保存/恢复执行现场”这个角度看，线程切换和进程切换是同一类操作。

### 关键区别
线程同属一个进程，共享地址空间，所以线程切换**不需要切换页表、不需要换地址空间**。

| 切换内容       | 线程切换（同进程） | 进程切换        |
| -------------- | ------------------ | --------------- |
| 寄存器、PC、SP | 要保存/恢复        | 要保存/恢复     |
| 栈             | 切换线程栈         | 切换栈          |
| 地址空间/页表  | 不切换，共享       | 要切换          |
| TLB            | 通常不需全刷新     | 可能需刷新/失效 |
| 文件描述符表   | 共享，不切换       | 可能切换        |
| 开销           | 较小               | 较大            |

所以线程切换通常比进程切换快，因为它省掉了地址空间切换和 TLB 相关开销。

### 什么时候发生？
- 如果可运行线程数 **多于 CPU 核心数**，同一个核心上就会分时运行，发生线程切换。
- 如果线程数 **少于等于核心数**，多个线程可能在不同核心上真正并行，不一定会互相切换。
- 线程也可能因为阻塞、时间片用完、被抢占、主动让出 CPU 等原因发生切换。

### 补充：用户级线程
如果是用户态实现的线程（比如协程、绿色线程），切换可以完全在用户态完成，不进入内核，开销更小。  
但像 Linux 的 `pthread` 通常是**内核级线程**，由内核调度，切换时仍会进入内核。

### 结论
对，线程之间也会发生类似进程的上下文切换，保存和恢复执行现场。  
但因为同一进程的线程共享地址空间，**线程切换通常比进程切换更轻量**，主要省去了页表、地址空间和 TLB 的切换开销。
