# 进程控制双剑客：fork 与 execve 深度笔记

## 一、 fork：从“分裂”到“写时复制”（进阶补充）

你明白 `fork()` 会创建一个子进程，并且父进程返回子进程 PID，子进程返回 0。在这里补充几个更底层的细节（面试和实战必考）：

### 1. 写时复制（Copy-On-Write, COW）
早期操作系统真的会把父进程的内存“物理复制”一份给子进程，这非常慢。
现代的 Linux 采用了 **COW 技术**：`fork()` 刚执行完时，父子进程**共享同一块物理内存页**，且权限被标记为“只读”。
只有当父子进程**某一方尝试修改内存**时，内核才会把那一页复制一份出来。这让 `fork()` 变得极其轻量和高效。

### 2. 文件描述符的共享
子进程会继承父进程的所有文件描述符（FD）。
*   如果父子进程共享同一个文件偏移量（比如读同一个文件），它们会互相影响（父进程读了一行，子进程接着读下一行）。
*   这也是为什么网络服务器里，父进程 bind 了端口监听 socket，`fork` 之后子进程可以直接接管这个 socket，因为它们是同一个文件描述符的引用。

### 3. `fork` 的返回值设计
看图里的代码：`if ((pid = Fork()) == 0)`。
为什么用 0 来判断子进程？因为 `fork()` 调用一次，返回两次。父进程需要拿到子进程的 PID 来进行后续管理（比如 `waitpid`），而子进程不需要自己的 PID（它随时可以 `getpid()`），所以操作系统让子进程拿到 0，用最简单的方式区分两者。

## 二、 execve：进程的“夺舍”

### 1. 什么是 execve？
`execve` 是 Unix/Linux 中 **`exec` 家族**（还有 `execl`, `execv`, `execvp` 等）中最底层的系统调用。
**核心概念：它并不是创建一个新进程，而是“替换”当前进程。**

*   **形象比喻**：你（当前进程）穿了一件“外壳”（代码、数据、堆栈、环境变量），`execve` 就是“夺舍”。它把外壳脱掉，换上一个全新的“灵魂”（新程序的代码和数据），但**你的躯壳（PID、文件描述符、优先级等）保持不变**。
*   **极其重要的原则**：**`execve` 一旦成功，就永远不会返回！** 调用它的后面的代码全都会被新程序覆盖掉。它只有失败的时候才会返回 -1。

### 2. 结合图片，`execve` 怎么用？

**函数原型**：`int execve(const char *pathname, char *const argv[], char *const envp[]);`

图片里清晰地展示了这三个参数在内存里长啥样：

#### ① `pathname`（路径）
看代码里写的是 `execve(myargv[0], myargv, environ)`。
而图中 `myargv[0]` 指针指向的字符串是 `"/bin/ls"`。
所以，它要执行的程序就是 `/bin/ls`。

#### ② `argv[]`（参数数组）
这是一个字符串指针数组，用来传给新程序的命令行参数。
*   **约定俗成**：`argv[0]` 必须是程序名本身。
*   **必须有结尾**：数组最后一个元素必须是 `NULL`，表示参数结束。
*   看图：`myargv[0]` -> `"/bin/ls"`
    *   `myargv[1]` -> `"-lt"`
    *   `myargv[2]` -> `"/usr/include"`
    *   `myargv[3]` -> `NULL`

#### ③ `envp[]`（环境变量数组）
这也是一个指针数组，存放着键值对字符串。
*   图中 `environ` 指针指向了 `envp` 数组。
*   比如：`envp[0]` -> `"USER=droh"`
    *   `envp[n-1]` -> `"PWD=/usr/droh"`
*   同样，**数组的最后一个元素必须是 `NULL`**。
*   代码里的 `environ` 是 C 语言标准库里预定义的一个全局变量，它直接指向当前进程的环境变量表。如果 `execve` 成功，新程序会继承这个环境变量表。

### 3. 代码逻辑解析（幻灯片下半部分）

```c
if ((pid = Fork()) == 0) {        // 在子进程中
    if (execve(myargv[0], myargv, environ) < 0) { // 执行新程序
        printf("%s: Command not found.\n", myargv[0]);
        exit(1);
    }
}
```

为什么 `execve` 要写在 `if < 0` 里面？
因为如果 `execve` 成功，它就不会回来了，下面的代码根本没机会跑。如果它返回了，说明它**失败**了（比如找不到 `/bin/ls`）。所以，一旦返回，我们立刻打印 "Command not found"，然后强制 `exit(1)` 退出子进程。

## 三、 终极总结：fork + execve = Shell

这套组合拳是操作系统里的经典范式：
1.  **Shell（父进程）** 读取用户输入的命令（比如 `ls -lt /usr/include`）。
2.  **Shell 调用 `fork()`** 复制出一个子进程。
3.  **子进程调用 `execve()`**，将自己的壳替换成 `/bin/ls`，开始执行任务。
4.  **父进程（Shell）** 知道子进程要去干活了，于是调用 `waitpid()` 挂起自己，等待子进程执行完毕。
5.  子进程执行完毕退出，父进程 `waitpid()` 返回，回收资源，再次打印提示符，等待用户下一次输入。

所以，图片里展示的就是一个**手写的微型 Shell** 在干活时的底层切片。



## execve 实战：参数到底怎么传？

### 1. 一般怎么写 `argv` 数组？
对，在调用 `execve` 之前，你必须在当前进程的内存里把这个数组组装好。
通常有两种方式：

**方式 A：硬编码（最简单，适合测试）**
```c
char *myargv[] = {"/bin/ls", "-lt", "/usr/include", NULL};
// 注意这里数组的类型是字符指针！
execve(myargv[0], myargv, environ);
```
这里第一参数 `myargv[0]` 就是 `"/bin/ls"`，第二参数 `myargv` 是整个数组。

**方式 B：动态构建（比如你自己写一个 Shell）**
如果是解析用户输入，你可能需要 `malloc` 或者用二维数组，先把用户敲的 `ls -lt /usr/include` 按空格拆开，塞进指针数组里，最后务必在末尾加上 `NULL`。

### 3. 进阶实战：为什么平时很少直接用 `execve`？

其实在写 Linux 程序时，我们很少直接调用 `execve`，因为它太底层了。它的核心痛点在于：**必须写绝对路径，且必须自己传环境变量。**

如果我想执行一个在系统 `PATH` 环境变量里的命令（比如 `ls`），我不知道它到底是 `/bin/ls` 还是 `/usr/bin/ls`。所以系统封装了一系列 `exec` 家族函数：

*   **`execlp` / `execvp`（最常用）**
    *   带 `p`（path）：你只需要传 `"ls"`，它会自动去 `environ` 里面的 `PATH` 中寻找可执行文件。
    *   带 `v`（vector）：接收数组，不用一个个传参。
    *   实战中，写一个简易 Shell，核心代码通常是：
        ```c
        if (fork() == 0) {
            // 子进程
            execvp(myargv[0], myargv); // 自动找路径，自动继承环境变量
            // 如果执行到这里，说明 execvp 失败了
            perror("execvp");
            exit(1);
        }
        // 父进程
        wait(NULL);
        ```
*   **`execve`** 其实是 `execvp` 等函数底层真正调用的**系统调用**。当你在系统编程（比如写操作系统内核、或者极其严苛的底层性能优化）时，才会直接用它。

### 4. 总结口诀
*   **一参是路**（`pathname`）：传字符串（`argv[0]` 或单独写 `"/bin/ls"`），**千万别加 `&`**。
*   **二参是表**（`argv`）：传指针数组（`argv` 或 `&argv[0]` 都一样，**末尾必须加 `NULL`**）。
*   **三参环境**（`envp`）：传环境变量数组（通常直接用全局变量 `environ`）。
*   **一旦成功，有去无回**：成功就夺舍，失败才返回 -1，必须紧接着写错误处理（比如 `perror` 和 `exit(1)`）。
