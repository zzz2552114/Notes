 别慌，虚拟机本身没事，只是你这个远程桌面会话的 GNOME Shell 挂了。原因很明确：

 │ Alt+F2 → r 只在本机 Xorg 会话里有效。在 xrdp（也就是增强会话）里，桌面是 xrdp-sesman 拉起来的，gnome-shell 退出后没
 │ 有任何东西会把它重新拉起来 —— 所以你看到的黑屏是"会话死了"，不是系统崩了。这一条是我上一条回复里的失误，抱歉，xrdp
 │ 会话里绝不能用这个。

 不用重装、不用重配 Hyper-V、HvSocket/安全启动那些设置都还在。按下面顺序恢复：

 ────────────────────────────────────────────────────────────────────────────────

 方案 A（先试，10 秒，最轻量）：把这个会话丢掉，重新连一次

 1. 完全关闭那个"虚拟机连接"窗口（点右上角 ×，不是最小化）。
 2. Hyper-V 管理器 → 右键 Ubuntu 24.04 LTS → 连接(C)...
 3. 如果弹出「显示配置」对话框（说明走增强会话）→ 拖滑块 → 「连接(N)」
 4. 出现 xrdp 登录框 → zhm + 密码 → 回车

 - 进去了 → 桌面回来了，直接跳到文末"以后怎么正确处理菜单问题"。
 - 如果登录框反复弹回、或提示 login failed → 说明旧会话变成僵尸还占着，走方案 B。

 ────────────────────────────────────────────────────────────────────────────────

 方案 B（推荐，几乎 100% 一次搞定）：重启虚拟机

 你还没往里装重要东西，重启是收益最高、最干净的做法，而且顺带把原来的右键菜单问题也一起解决了（因为重启后会话是"带着
 200% 缩放启动"的，ding 会按 200% 正确初始化）。

 1. Hyper-V 管理器 → 右键 Ubuntu 24.04 LTS → 关闭(Shut down)
     - 这是 ACPI 正常关机请求（你装过 hyperv-daemons，能正常关），等状态从"正在运行"变成"关闭"，一般 10~30 秒。
     - ⚠️ 不要点"保存状态(Save)"：那会把已经坏掉的图形会话一起存下来，下次开机继续黑屏。
 2. 等状态变「关闭」→ 右键 → 启动(S)
 3. 关掉旧的连接窗口 → 重新 连接(C)... → 「显示配置」→ 连上 → xrdp 登录 zhm + 密码
 4. 进桌面后：右键桌面空白处 → 菜单应该是完整的（不用再做任何"重启扩展"操作）

 如果「关闭」点了 1 分钟没反应（guest 卡住不响应 ACPI）：
 - 右键 → 重置(Reset)（相当于按电源键硬断电，ext4 有日志，Linux 能正常恢复；你没有未保存的重要数据，可以用）
 - 然后再「启动」

 ────────────────────────────────────────────────────────────────────────────────

 方案 C（不想动图形界面时的补救）：SSH 进去清僵尸会话

 1. 在 Windows 上直接查虚拟机 IP（不用进 guest，走集成服务上报）：
    ```powershell
      Get-VMNetworkAdapter -VMName 'Ubuntu 24.04 LTS' | select VMName,IPAddresses
    ```
 2. ssh zhm@<上面查到的IP>，登录后执行：
    ```bash
      loginctl list-sessions                 # 找到 Type=x11、且 Remote 的那个旧会话
      sudo loginctl terminate-user zhm       # 把 zhm 的所有会话清掉（最省事）
      sudo systemctl restart xrdp xrdp-sesman
      sudo reboot                            # 最保险
    ```
    （如果 SSH 也连不上，说明网络/虚拟机状态不对，回到方案 B 重置。）

 │ 也可以用「查看(V) → 取消勾选增强会话」回到基本会话控制台，在 vmconnect 里按 Ctrl+Alt+F3 切到文本终端登录 zhm 执行上
 │ 面的命令。但注意：不要在控制台图形界面里登录 zhm（xrdp + GNOME 同一时刻只支持一个图形会话，两边一起开又会黑屏）。

 ────────────────────────────────────────────────────────────────────────────────

 以后：解决"右键菜单被裁"的正确做法（两个安全方法）

 方法 1（安全，只重启桌面图标进程）——在 Ubuntu 终端里：

 ```bash
   pkill -f ding.js
   sleep 3
   pgrep -af ding.js      # 有输出说明扩展已自动把它拉起来
 ```

 右键桌面验证菜单是否完整。

 方法 2（安全，注销再登录）：

 ```bash
   gnome-session-quit --logout --no-prompt
 ```

 xrdp 会正常处理自己的会话，重新登录即可（不会黑屏）。

 方法 3（我现在更推荐你）：干脆重启一次虚拟机——正如方案 B 里说的，重启后 ding 就是按 200% 初始化的，问题自然不存在。

 ────────────────────────────────────────────────────────────────────────────────

 三条铁律（记住了以后不踩坑）

 1. 增强会话（xrdp）里永远不要用 Alt+F2 → r、killall gnome-shell 这类"重启桌面"的操作，会让你直接黑屏。要用 pkill -f
    ding.js 或注销。
 2. 别在运行中的会话里反复改显示缩放；改完就注销/重启一次，让桌面重新初始化。
 3. 每次连接时，「显示配置」里的分辨率拖到同一个位置，别每次都变，否则 ding 的几何又会失效。

 ────────────────────────────────────────────────────────────────────────────────

 现象（比如关机卡住、重置后进不去、xrdp 登录一直失败），把屏幕截图发我，我按现象继续定位。
