 ```bash

 四、第三步：客户机内部修复（诊断脚本 + 三项修改）

 ```bash

   ls -l /var/lib/oem-config/run 2>/dev/null && echo ">>> 文件存在：OEM 向导没收尾，xrdp 被 systemd 条件禁止启动" ||
 echo ">>> OK：文件不存在，OEM 已收尾"

   echo; echo "===== 2. xrdp 服务状态 + 是否被条件挡住 ====="
   systemctl status xrdp --no-pager | head -15
   systemctl is-enabled xrdp
   grep -Hn 'ConditionPathExists' /lib/systemd/system/xrdp.service /usr/lib/systemd/system/xrdp.service 2>/dev/null

   grep -nE '^(port|security_layer|crypt_level|bitmap_compression)' /etc/xrdp/xrdp.ini
   grep -nE 'FuseMountName|^startwm' /etc/xrdp/sesman.ini

   echo; echo "===== 4. vsock / hv_sock 内核模块 ====="
   cat /etc/modules-load.d/hyperv.conf
   lsmod | grep -E 'hv_sock|vsock' || echo "!! 没有加载 vsock/hv_sock"
   sudo modprobe hv_sock 2>&1; lsmod | grep -E 'hv_sock|vsock'

   echo; echo "===== 5. 自动登录 / Wayland / InitialSetup ====="
   grep -nE 'AutomaticLogin|WaylandEnable|InitialSetupEnable' /etc/gdm3/custom.conf

   echo; echo "===== 6. xrdp 日志 ====="
   sudo journalctl -u xrdp -b --no-pager | tail -30

   echo; echo "===== 7. 系统信息 ====="

 ### 根据输出做对应的三件事

 (A) 如果第 1 项显示 /var/lib/oem-config/run 存在
 说明 OEM 首次配置向导没有真正收尾（向导成功时会由 oem-config-wrapper 执行 rm -f /var/lib/oem-config/run 并重启）。xrdp
 因此被故意禁止启动。你已经建好 zhm 账号了，可以手动收尾（等价于向导成功路径做的事）：

 ```bash
   sudo rm -f /var/lib/oem-config/run
   sudo systemctl disable --now oem-config.service oem-config.target 2>/dev/null
   sudo systemctl set-default graphical.target
   sudo deluser --force --remove oem 2>/dev/null     # 删临时 oem 用户，可选
 ```

 (B) 关掉"自动登录"（官方文档明确说它会破坏增强会话；增强会话本身就是一次 RDP 登录，必须走密码认证）：

 ```bash
   sudo sed -i 's/^AutomaticLoginEnable=.*/AutomaticLoginEnable=false/' /etc/gdm3/custom.conf
   sudo sed -i '/^AutomaticLogin=/d' /etc/gdm3/custom.conf
   grep -nE 'AutomaticLogin|WaylandEnable' /etc/gdm3/custom.conf    # 复核
 ```

 （图形界面也可以：设置 → 系统 → 用户 → 关闭"自动登录"）

 (C) 确认 xrdp 配置没被动过、然后启用并启动它

 ```bash

   sudo grep -n '^port=' /etc/xrdp/xrdp.ini
   # 如需恢复（只在确实是 port=3389 时才执行）：
   # sudo sed -i 's|^port=3389$|port=vsock://-1:3389|' /etc/xrdp/xrdp.ini

   sudo systemctl enable xrdp
   sudo systemctl start xrdp
   systemctl status xrdp --no-pager | head -20
   sudo journalctl -u xrdp -b --no-pager | tail -20
 ```

 期望：active (running)，日志里没有 vsock 绑定失败。注意别去把 port 改成 3389 或 tcp://，那是镜像刻意设成 vsock-only 的
 ，改了反而连不上。

   ls -l /var/lib/oem-config/run 2>/dev/null && echo ">>> 文件存在：OEM 向导没收尾，xrdp 被 systemd 条件禁止启动" ||
 echo ">>> OK：文件不存在，OEM 已收尾"

   echo; echo "===== 2. xrdp 服务状态 + 是否被条件挡住 ====="
   systemctl status xrdp --no-pager | head -15
   systemctl is-enabled xrdp
   grep -Hn 'ConditionPathExists' /lib/systemd/system/xrdp.service /usr/lib/systemd/system/xrdp.service 2>/dev/null

   echo; echo "===== 3. xrdp 关键配置（应含 vsock://-1:3389、security_layer=rdp、crypt_level=none）====="
   grep -nE '^(port|security_layer|crypt_level|bitmap_compression)' /etc/xrdp/xrdp.ini
   grep -nE 'FuseMountName|^startwm' /etc/xrdp/sesman.ini

   echo; echo "===== 4. vsock / hv_sock 内核模块 ====="
   cat /etc/modules-load.d/hyperv.conf
   lsmod | grep -E 'hv_sock|vsock' || echo "!! 没有加载 vsock/hv_sock"
   sudo modprobe hv_sock 2>&1; lsmod | grep -E 'hv_sock|vsock'

   echo; echo "===== 5. 自动登录 / Wayland / InitialSetup ====="
   grep -nE 'AutomaticLogin|WaylandEnable|InitialSetupEnable' /etc/gdm3/custom.conf

   echo; echo "===== 6. xrdp 日志 ====="
   sudo journalctl -u xrdp -b --no-pager | tail -30

   echo; echo "===== 7. 系统信息 ====="
   lsb_release -ds; uname -r; echo "用户: $(id -un) 主机: $(hostname)"
 ```

 ### 根据输出做对应的三件事

 (A) 如果第 1 项显示 /var/lib/oem-config/run 存在
 说明 OEM 首次配置向导没有真正收尾（向导成功时会由 oem-config-wrapper 执行 rm -f /var/lib/oem-config/run 并重启）。xrdp
 因此被故意禁止启动。你已经建好 zhm 账号了，可以手动收尾（等价于向导成功路径做的事）：

 ```bash
   sudo rm -f /var/lib/oem-config/run
   sudo systemctl disable --now oem-config.service oem-config.target 2>/dev/null
   sudo systemctl set-default graphical.target
   sudo deluser --force --remove oem 2>/dev/null     # 删临时 oem 用户，可选
 ```

 (B) 关掉"自动登录"（官方文档明确说它会破坏增强会话；增强会话本身就是一次 RDP 登录，必须走密码认证）：

 ```bash
   sudo sed -i 's/^AutomaticLoginEnable=.*/AutomaticLoginEnable=false/' /etc/gdm3/custom.conf
   sudo sed -i '/^AutomaticLogin=/d' /etc/gdm3/custom.conf
   grep -nE 'AutomaticLogin|WaylandEnable' /etc/gdm3/custom.conf    # 复核
 ```

 （图形界面也可以：设置 → 系统 → 用户 → 关闭"自动登录"）

 (C) 确认 xrdp 配置没被动过、然后启用并启动它

 ```bash
   # 检查：必须能看到 port=vsock://-1:3389。若显示 port=3389，说明被 apt upgrade 覆盖过，需要改回：
   sudo grep -n '^port=' /etc/xrdp/xrdp.ini
   # 如需恢复（只在确实是 port=3389 时才执行）：
   # sudo sed -i 's|^port=3389$|port=vsock://-1:3389|' /etc/xrdp/xrdp.ini

   sudo systemctl enable xrdp
   sudo systemctl start xrdp
   systemctl status xrdp --no-pager | head -20
   sudo journalctl -u xrdp -b --no-pager | tail -20
 ```

 期望：active (running)，日志里没有 vsock 绑定失败。注意别去把 port 改成 3389 或 tcp://，那是镜像刻意设成 vsock-only 的
 ，改了反而连不上。
