# 子查询：查询里面的查询

先看一个简单例子：

```sql
SELECT student_name
FROM students
WHERE student_id IN (
    SELECT student_id
    FROM enrollments
    WHERE score >= 90
);
```

外层在问：

> 哪些学生？

内层在产生：

> 分数至少 90 的学生 id。

所谓子查询，就是**一个查询嵌在另一个查询里面**。括号里那个 `SELECT` 先跑，把结果交给外层用。

---

## 一、子查询三类最常见用法

看到子查询，先问：这个子查询最后是在产生**一个值**？**一列值**？还是"**存在/不存在**"？这样就不会乱。

### A. 当一个值（标量子查询）

```sql
WHERE score > (
    SELECT AVG(score)
    FROM enrollments
)
```

内层 `SELECT AVG(score)` 返回的是**单个数字**（全校平均分），外层就能用 `>` 去比较："找出成绩高于全校平均分的记录"。

完整一点：

```sql
SELECT student_id, score
FROM enrollments
WHERE score > (SELECT AVG(score) FROM enrollments);
```

### B. 当一个集合（IN 子查询）

```sql
WHERE student_id IN (
    SELECT student_id
    FROM enrollments
)
```

内层返回的是**一列 student_id**（所有选过课的学生 id），外层用 `IN` 判断"我的 student_id 在不在这列里"。

### C. 当存在性判断（EXISTS / NOT EXISTS）

```sql
WHERE EXISTS (
    SELECT 1
    FROM enrollments e
    WHERE e.student_id = s.student_id
)
```

外层是 students 的每一行 s，内层检查"有没有一条 enrollments 记录，它的 student_id 等于当前这个学生 s.student_id"。有就 TRUE，没有就 FALSE。

> 注意！！！`EXISTS` 里面写 `SELECT 1` 还是 `SELECT *` 还是 `SELECT 任何列` 都一样——EXISTS 只关心"有没有行"，不关心选了哪一列。写 `SELECT 1` 是惯例，表示"我不关心列，只关心存在性"。

## 二、NOT IN 的 NULL 陷阱（极其重要）

例如：

```sql
WHERE student_id NOT IN (
    SELECT student_id
    FROM enrollments
)
```

如果子查询结果里可能出现 NULL，`NOT IN` 会受到三值逻辑影响，结果可能和直觉完全不一样。

原理：`x NOT IN (a, b, NULL)` 展开成 `x <> a AND x <> b AND x <> NULL`。而 `x <> NULL` 的结果是 **UNKNOWN**。在 AND 运算里，只要有一个 UNKNOWN，整个表达式就不可能是 TRUE——于是这一行被 WHERE 过滤掉了。

结果就是：**只要子查询结果里有一个 NULL，`NOT IN` 会把外层所有行都过滤光**（返回空集），和你的直觉完全相反。

所以在"找不存在的对应行"时，常见而稳妥的思路是：

```sql
WHERE NOT EXISTS (
    SELECT 1
    FROM enrollments e
    WHERE e.student_id = s.student_id
)
```

`NOT EXISTS` 不做集合成员比较，只判断"有没有匹配行"，不受 NULL 污染。

> 记忆法：**"找不存在的"一律用 NOT EXISTS，别用 NOT IN。** NOT IN 一旦遇到 NULL 就整个翻车，而你很难保证子查询结果里永远没有 NULL。

这不是要求你现在就熟练写，而是先把"存在性查询"和"集合包含"区分开。

## 三、关联子查询 vs 非关联子查询（进阶）

### 1. 非关联子查询（不相关子查询）

内层子查询**独立于外层**，它不引用外层的任何列，所以**只执行一次**，算出结果后交给外层反复用。

```sql
SELECT student_id, score
FROM enrollments
WHERE score > (SELECT AVG(score) FROM enrollments);
```

内层 `SELECT AVG(score)` 跟外层的当前行没关系，先算一次平均分，然后外层拿这个固定值去比每一行。

### 2. 关联子查询（相关子查询）

内层子查询**引用了外层查询的列**，于是外层每处理一行，内层都要**重新执行一次**。

```sql
SELECT student_name
FROM students s
WHERE EXISTS (
    SELECT 1
    FROM enrollments e
    WHERE e.student_id = s.student_id   -- 引用了外层 s.student_id
);
```

外层 students 有 100 行，内层就跑 100 次——每次拿当前这个学生的 id 去 enrollments 里查有没有记录。

### 3. 对比

| 对比项 | 非关联子查询 | 关联子查询 |
|---|---|---|
| 是否引用外层列 | 否 | 是 |
| 执行次数 | 一次 | 外层每行一次 |
| 典型 | `WHERE score > (SELECT AVG...)` | `WHERE EXISTS (SELECT ... WHERE e.x = s.x)` |
| 性能 | 通常较好（只算一次） | 可能较慢（逐行跑），但优化器常能改写成 JOIN |

## 四、子查询在 FROM 中（派生表 / Derived Table）

子查询写在 FROM 后面，相当于临时造一张表：

```sql
SELECT avg_tbl.course_id, avg_tbl.avg_score
FROM (
    SELECT course_id, AVG(score) AS avg_score
    FROM enrollments
    GROUP BY course_id
) AS avg_tbl
WHERE avg_tbl.avg_score >= 80;
```

内层先算出"每门课平均分"这张临时表 `avg_tbl`，外层再在它上面过滤。

> 注意！！！**FROM 里的子查询必须起别名**（这里的 `AS avg_tbl`）。因为 FROM 后面的东西都得是一张"有名字的表"，不起别名数据库不知道怎么引用它。这是硬性语法要求。

派生表和 CTE（WITH）功能上很像，CTE 可读性更好，后面 CTE 章节会专门对比。

---

## 五、子查询在 SELECT 中（标量子查询）

子查询写在 SELECT 的列位置，必须**返回一行一列**：

```sql
SELECT
    student_name,
    (SELECT AVG(score) FROM enrollments) AS global_avg
FROM students;
```

这个子查询给每一行都附上"全校平均分"这一列。

> 注意！！！标量子查询**只能返回一行一列**。如果它返回多行，数据库直接报错（"子查询返回多于一行"）；返回多列也报错。想保险，就在子查询里用聚合函数（必然一行）或加 `LIMIT 1`。

## 六、EXISTS vs IN 的选择（深度展开）

### 1. NULL 陷阱的差异

- `IN`：`x IN (a, b, c)` 是集合成员判断，遇到 NULL 结果是 UNKNOWN。
- `EXISTS`：只判断"有没有行"，不做值比较，**不受 NULL 影响**。

这就是为什么 `NOT IN` 危险而 `NOT EXISTS` 安全（见第二节）。

### 2. 性能对比

- **旧版本数据库**：`EXISTS` 通常更快，因为它找到第一条匹配就停（短路），不用把整个内层结果物化成集合。
- **现代优化器**：很多数据库会把 `IN` 子查询自动改写成半连接（Semijoin），把 `EXISTS` 也改写成半连接，**两者最终执行计划可能一模一样**。

### 3. 什么时候用哪个

| 场景 | 推荐 |
|---|---|
| 内层结果是一列明确的值、想判断成员关系 | `IN` |
| "找存在/不存在的对应行"，尤其可能有 NULL | `EXISTS` / `NOT EXISTS` |
| 找"不存在的" | **一律 NOT EXISTS** |

## 七、子查询展开（Subquery Unnesting，进阶）

现代数据库有个重要优化叫**子查询上拉/展开**：优化器会自动把很多子查询改写成 JOIN，而不是傻乎乎地"先跑内层再跑外层"。

- `IN (SELECT ...)` → 常被改写成 **Semijoin**；
- `EXISTS (SELECT ...)` → 改写成 **Semijoin**；
- `NOT EXISTS` → 改写成 **Antijoin**；
- FROM 里的派生表 → 常被**合并进外层查询**（条件下推）。

所以你今天写的 `WHERE student_id IN (SELECT ...)`，底层可能就是一个高效的连接。这也是现代数据库里子查询和 JOIN 性能差距越来越小的原因。

---

## 八、横向子查询 LATERAL（进阶）

普通子查询在 FROM 里不能引用外层表的列。`LATERAL` 允许它引用——外层每一行，都执行一次这个子查询。

```sql
SELECT s.student_name, top2.score
FROM students s
JOIN LATERAL (
    SELECT e.score
    FROM enrollments e
    WHERE e.student_id = s.student_id
    ORDER BY e.score DESC
    LIMIT 2
) top2 ON TRUE;
```

这就是"每个学生取成绩最高的两门课"。它和关联子查询是近亲，但 LATERAL 子查询能返回**多行多列**（放进 FROM 当表用），而 SELECT 里的标量子查询只能返回一行一列。

## 九、ALL / ANY / SOME 与子查询配合

这三个量词和子查询搭配，做"和集合里所有/任意元素比较"：

```sql
-- score 大于内层结果里的每一个值（即大于最高分）
WHERE score > ALL (SELECT score FROM enrollments WHERE course_id = 1);

-- score 大于内层结果里的任意一个值
WHERE score > ANY (SELECT score FROM enrollments WHERE course_id = 1);
```

等价关系：

- `> ALL (集合)` ≡ 大于集合里最大值；
- `> ANY (集合)` ≡ 大于集合里最小值（只要比其中一个大就行）；
- `= ANY (集合)` ≡ `IN (集合)`；
- `<> ALL (集合)` ≡ `NOT IN (集合)`（注意这又带回了 NULL 陷阱）。

> 注意！！！`SOME` 是 `ANY` 的别名，两者完全等价。

## 十、行子查询（Row Subquery）

子查询还能返回**一行多列**，和"行构造器"配合做多列比较：

```sql
WHERE (student_id, course_id) IN (
    SELECT student_id, course_id
    FROM enrollments
    WHERE score >= 90
);
```

这里 `(student_id, course_id)` 是一个"行值"，和内层返回的两行结果做配对比较。意思是："这个学生+这门课的组合，有没有出现在 90 分以上的记录里"。比写两个 `AND` 条件紧凑。

---

## 十一、子查询里的 ORDER BY

子查询里单独写 `ORDER BY` 通常**没有意义**——因为外层怎么用这个结果是外层决定的，内层排了序也保不住。

唯一例外是配合 `LIMIT`：

```sql
WHERE score > (
    SELECT score FROM enrollments
    ORDER BY score DESC
    LIMIT 1
)
```

这里 `ORDER BY ... LIMIT 1` 是为了取出"最高分"，排序本身是为 LIMIT 服务的，有实际意义。

---

## 十二、子查询 vs CTE

子查询嵌套多了就变成"洋葱代码"，一层套一层，得从最里面往外读。CTE（`WITH`）可以把逻辑扁平化，给每个中间结果起名字。两者能力重叠，**可读性优先时用 CTE**。详细对比见 CTE 章节。
