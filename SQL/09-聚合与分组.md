# 聚合与分组：GROUP BY / HAVING

先认识这些聚合函数：

```text
COUNT   计数
SUM     求和
AVG     平均值
MIN     最小值
MAX     最大值
```

它们的共同特点：**把多行折成一行**。你给它一堆行，它吐出一个汇总值。

---

## 一、COUNT(*)

```sql
SELECT COUNT(*)
FROM students;
```

表示：

> 当前结果里有多少行。

`COUNT(*)` 不看具体某一列，它就是数"有几行"。哪怕整行所有列都是 NULL，只要这一行存在，`COUNT(*)` 就数它。

---

## 二、COUNT(column)

```sql
SELECT COUNT(age)
FROM students;
```

表示：

> age 不为 NULL 的行有多少。

这是初学者特别容易搞错的点。

> 注意！！！`COUNT(*)` 和 `COUNT(列)` 不是一回事：
> - `COUNT(*)` 数**行数**，不管列是不是 NULL；
> - `COUNT(age)` 只数 **age 列非 NULL 的行**。
>
> 表里有 100 个学生，但其中 10 个人 age 是 NULL，那么 `COUNT(*)` = 100，`COUNT(age)` = 90。

记忆法：想数"有多少条记录"用 `COUNT(*)`；想数"某个字段有值的有几条"才用 `COUNT(列)`。

---

## 三、AVG / SUM / MIN / MAX

```sql
SELECT AVG(score)
FROM enrollments;
```

- `SUM(score)`：所有成绩加起来；
- `AVG(score)`：平均分（= SUM / 非 NULL 行数）；
- `MIN(score)`：最低分；
- `MAX(score)`：最高分。

> 注意！！！这四个函数都**自动忽略 NULL**。如果某行 score 是 NULL，SUM 不算它、AVG 的分母也不算它、MIN/MAX 也跳过它。这和 `COUNT(*)` 不忽略 NULL 形成对比，后面有专门对比表。

---

## 四、GROUP BY

例如：

```sql
SELECT course_id, COUNT(*) AS cnt
FROM enrollments
GROUP BY course_id;
```

理解成：

> 按 course_id 把行分成一组一组，然后每组算 COUNT。

---

## 五、GROUP BY 为什么会"压缩结果"？

原始：

```text
数学
数学
英语
英语
英语
```

按课程分组以后，从"五行"变成了：

```text
数学   2
英语   3
```

所以：

```text
GROUP BY = 把多行折成组
```

没有 GROUP BY 时，整个结果集是一个大组，聚合函数对全部行算一个值；有了 GROUP BY，数据库先按你指定的列把行"分门别类"，然后**每一类各算一个聚合值**。一组出一行，所以结果行数变少了。

---

## 六、GROUP BY 多列分组

GROUP BY 后面可以跟多列，表示"按这些列的**组合**分组"。

```sql
SELECT course_id, student_id, COUNT(*)
FROM enrollments
GROUP BY course_id, student_id;
```

意思是：course_id 和 student_id 都相同的行，才算同一组。这是"二维分组"——既按课分、又按学生分。

---

## 七、HAVING

```sql
SELECT course_id, COUNT(*) AS cnt
FROM enrollments
GROUP BY course_id
HAVING COUNT(*) >= 2;
```

顺序：

```text
WHERE → 先删掉某些行
GROUP BY → 把剩余行分组
HAVING → 再删掉某些组
```

最重要的一句话：

```text
WHERE 管行，HAVING 管组。
```

- `WHERE` 在分组**之前**过滤，针对的是原始行；
- `HAVING` 在分组**之后**过滤，针对的是聚合后的组，所以 HAVING 里**能写聚合函数**（比如 `COUNT(*) >= 2`）。

> 注意！！！**WHERE 里不能写聚合函数**。你不能写 `WHERE COUNT(*) >= 2`，因为 WHERE 执行时还没分组、还没算出 COUNT。想按聚合结果过滤，只能用 HAVING。

---

## 八、SELECT 合规性

例如：

```sql
SELECT
    course_id,
    student_id,
    COUNT(*)
FROM enrollments
GROUP BY course_id;
```

你会问：

> 一个 course_id 组里可能有多个 student_id，到底该显示哪个？

数据库当然不知道。

所以一般来说，SELECT 中：

- 要么是分组列；
- 要么是聚合结果；
- 要么是能够从分组列唯一确定的表达式（这里先不要靠这个绕规则）。

初学阶段直接记：

```text
SELECT 里的普通列，通常必须出现在 GROUP BY。
```

---

## 九、GROUP BY 标准合规性深度讲解（进阶）

### 1. ONLY_FULL_GROUP_BY 规则

SQL 标准要求：SELECT 里出现的**非聚合列**，必须要么出现在 GROUP BY 里，要么**函数依赖于** GROUP BY 的列。这就是 `ONLY_FULL_GROUP_BY`。

为什么有这个规则？因为前面那个例子——`GROUP BY course_id` 却 SELECT `student_id`——一个组里有多个 student_id，数据库随便挑一个给你，结果是不确定的、不可复现的。标准要杜绝这种"看着能跑、其实结果随机"的写法。

### 2. 各数据库行为差异

| 数据库 | 行为 |
|---|---|
| MySQL（默认开启 ONLY_FULL_GROUP_BY） | 严格模式下，SELECT 非聚合列必须在 GROUP BY 里，否则报错 |
| MySQL（关掉该模式） | 允许 SELECT 不在 GROUP BY 里的列，随便取组内某一行的值（危险） |
| PostgreSQL | 做**功能依赖检测**：如果某列能从 GROUP BY 的列唯一确定（比如 GROUP BY 主键，那表里其他列都函数依赖于它），就允许 SELECT；否则报错 |
| SQL Server / Oracle | 严格要求非聚合列必须在 GROUP BY 里 |

> 注意！！！别依赖 MySQL 那种"放松模式"。它今天能跑，明天换数据库、或哪天开启严格模式就报错。**养成"SELECT 里的普通列一律出现在 GROUP BY"的习惯，到哪都对。**

## 十、GROUPING SETS / ROLLUP / CUBE：多维汇总（进阶）

有时候你一张报表里**同时要不同维度的小计和总计**，写多个 GROUP BY 再 UNION 很啰嗦。SQL 提供了三个"超级分组"语法。

### 1. GROUPING SETS（多维分组）

显式列出你想要哪些分组组合：

```sql
SELECT major, course_id, COUNT(*)
FROM students s
JOIN enrollments e ON e.student_id = s.student_id
GROUP BY GROUPING SETS (
    (major),          -- 按专业汇总
    (course_id),      -- 按课程汇总
    (major, course_id),  -- 按专业+课程汇总
    ()                -- 总计（空集 = 全表一行）
);
```

它等价于把 `GROUP BY major`、`GROUP BY course_id`、`GROUP BY major, course_id`、以及全表 COUNT 四个结果 `UNION ALL` 起来。好处是**只扫一遍表**，不用扫四遍。

### 2. ROLLUP（层级汇总）

按层级从细到粗逐级汇总：

```sql
SELECT major, course_id, COUNT(*)
FROM ...
GROUP BY ROLLUP (major, course_id);
```

它产生的分组组合是：

```text
(major, course_id)   -- 最细：每个专业每门课
(major)              -- 专业小计
()                   -- 总计
```

典型用于时间维度：`GROUP BY ROLLUP (年, 月, 日)` 自动给出每日、每月、每年和总计。

### 3. CUBE（全维度组合）

`CUBE` 给出所有可能的维度组合：

```sql
GROUP BY CUBE (major, course_id);
```

产生：

```text
(major, course_id)
(major)
(course_id)
()
```

### 4. 三者对比

| 语法 | 产生的分组 | 适用 |
|---|---|---|
| GROUPING SETS | 你显式列出的组合 | 只要特定几个维度 |
| ROLLUP | 层级前缀组合（从细到粗） | 时间/地区层级汇总 |
| CUBE | 所有维度的全部组合 | 全方位交叉分析 |

> 注意！！！这三个语法 MySQL 8.0+ 才支持，PostgreSQL、Oracle 都支持。汇总行里"没参与这一层分组"的列会显示为 NULL，你可以用 `GROUPING(列)` 函数判断某行是不是某个维度的汇总行。

## 十一、聚合函数中的 DISTINCT

聚合函数里可以加 `DISTINCT`，表示"先去重再聚合"：

```sql
-- 统计有多少个不同的专业
SELECT COUNT(DISTINCT major) FROM students;

-- 对去重后的成绩求和
SELECT SUM(DISTINCT score) FROM enrollments;
```

`COUNT(DISTINCT major)` = "major 有多少种不同的值"，而不是"有多少行"。

> 注意！！！`COUNT(*)` 永远不去重；`COUNT(DISTINCT 列)` 才去重。别把"行数"和"不同值个数"搞混。

---

## 十二、FILTER 子句在聚合中的使用（PostgreSQL 特有）

和 CASE 章节讲的一样，PostgreSQL 给聚合加条件可以用 `FILTER`：

```sql
SELECT
    course_id,
    COUNT(*) FILTER (WHERE score >= 60) AS pass_cnt,
    AVG(score) FILTER (WHERE score >= 60) AS pass_avg
FROM enrollments
GROUP BY course_id;
```

等价于条件聚合：

```sql
AVG(CASE WHEN score >= 60 THEN score END)
```

区别：`FILTER` 写法更直观，且只在 PostgreSQL 可用；`CASE WHEN` 通用。

---

## 十三、聚合函数对 NULL 的处理（对比表）

| 聚合函数 | 遇到 NULL 怎么办 |
|---|---|
| `COUNT(*)` | **不忽略**，照样数行 |
| `COUNT(列)` | **忽略**该列是 NULL 的行 |
| `SUM(列)` | **忽略** NULL 行 |
| `AVG(列)` | **忽略** NULL 行（分母也是非 NULL 行数） |
| `MIN(列)` | **忽略** NULL |
| `MAX(列)` | **忽略** NULL |

> 注意！！！一个经典陷阱：`AVG(score)` 不是"所有学生的平均"，而是"所有**有成绩的学生**的平均"。缺考的学生（score 为 NULL）被分母排除了。如果你想把缺考当 0 分算平均，得先 `COALESCE(score, 0)` 补 0 再 AVG。

---

## 十四、GROUP BY 与 NULL 的交互

GROUP BY 把"值相同"的行分到一组。那么 NULL 呢？

> **所有 NULL 被分到同一组。**

SQL 规定：在 GROUP BY 里，`NULL = NULL` 被视为相等（和 WHERE 里 `NULL = NULL` 是 UNKNOWN 不一样！）。所以 major 为 NULL 的所有学生，会自动聚成一组。

```sql
SELECT major, COUNT(*)
FROM students
GROUP BY major;
```

结果里会有一行 major 显示为 NULL，代表"专业未知"的那组人数。

---

## 十五、空组的处理

```sql
SELECT course_id, COUNT(*)
FROM enrollments
WHERE score >= 100      -- 假设根本没有人考到 100
GROUP BY course_id;
```

如果 WHERE 把所有行都过滤光了，那么**一行都不剩**，GROUP BY 没有任何组可分，结果是**空集**（0 行），不是"一行 NULL"。

对比：

```sql
SELECT COUNT(*) FROM enrollments WHERE score >= 100;
```

没有 GROUP BY 时，即使没有任何行匹配，聚合函数也会返回**一行**（COUNT = 0），因为"整个空表"也算一个组。

> 记忆法：**有 GROUP BY 时，过滤光了就什么都不返回（空集）；没有 GROUP BY 时，聚合函数永远返回一行（空表算一个组）。**

## 十六、HAVING 与 WHERE 的执行顺序深度对比

完整的 SELECT 执行顺序（逻辑顺序）是：

```text
FROM / JOIN     先把表连好
WHERE           按行过滤
GROUP BY        分组
聚合函数         每组算聚合
HAVING          按组过滤
SELECT          算出要输出的列
ORDER BY        排序
LIMIT           截取
```

这就解释了：
- **WHERE 里不能用聚合**：因为 WHERE 执行时还没 GROUP BY、还没算聚合。
- **WHERE 里可以用普通列**：因为普通列在 WHERE 阶段已经存在。
- **HAVING 里能用聚合**：因为 HAVING 在 GROUP BY 和聚合之后。
- **WHERE 比 HAVING 更高效**：WHERE 先过滤掉大量行，分组和聚合要处理的行就少了；能用 WHERE 过滤的，尽量别堆到 HAVING。

> 注意！！！能用 WHERE 提前过滤的条件（不依赖聚合的），放 WHERE 里性能更好。HAVING 只用来过滤"分组后的聚合结果"。

## 十七、更多聚合函数（进阶）

除了五个基本的，还有一堆专用聚合函数：

| 函数 | 作用 | 示例 |
|---|---|---|
| `STRING_AGG(col, sep)` | 把一组值拼成一个字符串 | `STRING_AGG(student_name, ', ')` |
| `ARRAY_AGG(col)` | 把一组值聚成数组 | `ARRAY_AGG(score)` |
| `JSON_AGG(col)` | 聚成 JSON 数组 | `JSON_AGG(...)` |
| `BOOL_AND(expr)` | 组内全部为 TRUE 才 TRUE | `BOOL_AND(score >= 60)` |
| `BOOL_OR(expr)` | 组内任一为 TRUE 就 TRUE | `BOOL_OR(score >= 90)` |
| `EVERY(expr)` | 同 BOOL_AND（标准名） | |
| `PERCENTILE_CONT(x)` | 连续百分位数 | `PERCENTILE_CONT(0.5)` 中位数 |
| `PERCENTILE_DISC(x)` | 离散百分位数 | |
| `CORR / COVAR_POP` | 相关系数、协方差 | 统计分析 |

### STRING_AGG 里的排序

很多聚合函数支持在内部 `ORDER BY`：

```sql
SELECT course_id,
       STRING_AGG(student_name, ', ' ORDER BY score DESC) AS top_students
FROM enrollments
GROUP BY course_id;
```

这表示：每组里，按 score 从高到低把学生名拼起来。`ARRAY_AGG(col ORDER BY col)` 同理。

## 十八、聚合的性能考虑（进阶）

数据库做 GROUP BY 主要有两种执行方式：

- **Hash Aggregate（哈希聚合）**：扫描分组列，建一张哈希表，key 是分组值、value 是累加的聚合状态。适合基数（不同分组值个数）不太大的场景，**不需要排序**。
- **Sort Aggregate（排序聚合）**：先把数据按分组列**排序**，相同值自然排在一起，然后顺序扫一遍就能累计每组。适合分组列已经有序、或数据量特别大的场景。

> 记忆法：**数据量大、分组值不多 → Hash Aggregate；数据本来就按分组列有序 → Sort Aggregate 更省。** 看执行计划时能区分这两种，就知道优化器选得合不合理。

另外，旧版本 PostgreSQL 里 `GROUP BY` 会顺带排序输出结果（因为用了 Sort Aggregate），但这**不是保证**——新版本默认用 Hash Aggregate，GROUP BY 的结果顺序就不一定了。**别依赖 GROUP BY 自动排序，要排序就显式写 ORDER BY。**
