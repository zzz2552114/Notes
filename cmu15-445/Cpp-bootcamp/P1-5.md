`std::move` 本身不移动任何东西，它只是把表达式强制转换成“右值引用”，让编译器去选择移动构造/移动赋值。真正有没有拷贝、有没有移动，要看**具体调用了哪个构造函数/赋值函数**。

你这段测试里，关键点就一句话：

- **拷贝一个 `vector`**：新分配一块缓冲区，然后对每个元素调用元素的拷贝构造。
- **移动一个 `vector`**：不新分配、不碰元素，只把 `vector` 内部的三个指针/大小/容量“偷”过来，源 `vector` 置空。元素还在原来的堆内存里，原地不动。

所以：

```cpp
auto copied = src;            // vector 拷贝构造：n 个 Tracked 被拷贝构造
auto moved = std::move(src);  // vector 移动构造：0 个 Tracked 被拷贝/移动构造
```

---

## 1. 你的 `Tracked` 计数在哪里增加？

```cpp
struct Tracked {
    inline static int copies = 0, moves = 0;
    int v;

    explicit Tracked(int x) : v(x) {}   // 不增加 copies/moves

    Tracked(const Tracked& other) : v(other.v) {
        ++copies;                        // 只有这里增加 copies
    }

    Tracked(Tracked&& other) noexcept : v(other.v) {
        ++moves;                         // 只有这里增加 moves
    }

    static void Reset() {
        copies = 0, moves = 0;           // 清零
    }
};
```

所以：

- 调用 `Tracked(const Tracked&)` → `copies++`
- 调用 `Tracked(Tracked&&)` → `moves++`
- 调用 `Tracked(int)` → 都不加

---

## 2. 测试点逐行看：哪里有拷贝，哪里有 move？

### 2.1 填充 `src`

```cpp
const int n = 1000;
std::vector<Tracked> src;
src.reserve(n);
for (int i = 0; i < n; ++i) src.emplace_back(i);
```

这里：

- `reserve(n)` 先分配好缓冲区。
- `emplace_back(i)` 直接在缓冲区里构造 `Tracked`，调用的是 `Tracked(int)`。
- 没有调用拷贝构造，也没有调用移动构造。
- 即使 `emplace_back` 触发扩容，也只会移动旧元素；但你 `reserve` 了，所以不会扩容。

然后：

```cpp
Tracked::Reset();
```

计数清零。

---

### 2.2 `auto copied = src;`

```cpp
auto copied = src;
```

`src` 是左值，所以调用的是 `std::vector<Tracked>` 的**拷贝构造**。

`vector` 拷贝构造会：

1. 分配一块新的堆内存；
2. 对 `src` 里的每个 `Tracked` 元素，调用 `Tracked(const Tracked&)`；
3. 放到新内存里。

所以：

```cpp
BT_CHECK_EQ(Tracked::copies, n);  // 每个元素被拷贝一次
BT_CHECK_EQ(Tracked::moves, 0);   // 没有移动
```

这里就是 **n 次元素级拷贝**。

---

### 2.3 `auto moved = std::move(src);`

```cpp
Tracked::Reset();
auto moved = std::move(src);
```

`std::move(src)` 只是把 `src` 转成 `std::vector<Tracked>&&`，它本身不移动。

真正发生的是：

```cpp
std::vector<Tracked> moved = std::vector<Tracked>&&(src);
```

也就是调用 `std::vector<Tracked>` 的**移动构造**。

`vector` 移动构造不会逐个移动元素。它只是：

```cpp
moved.begin = src.begin;
moved.end = src.end;
moved.cap = src.cap;
src.begin = src.end = src.cap = nullptr; // 通常置空
```

元素对象本身还在原来那块堆内存里，只是现在由 `moved` 管理。

所以：

```cpp
BT_CHECK_EQ(Tracked::copies, 0);  // 没有元素被拷贝
BT_CHECK_EQ(Tracked::moves, 0);   // 也没有元素被移动
```

这就是为什么 `vector` 移动是 O(1) 的：只偷缓冲区，不碰元素。

---

### 2.4 `auto b = std::move(a);` 对 `vector<string>`

```cpp
auto a = MakeLongStrings(n);
auto b = std::move(a);
```

同理，`a` 是 `std::vector<std::string>`。

`std::move(a)` 只是转右值，`b` 调用 `vector<string>` 的移动构造。

`vector<string>` 移动构造同样只偷 `vector` 的缓冲区指针，不会调用每个 `std::string` 的移动构造。

所以这里也是：

- 0 次 `std::string` 拷贝构造；
- 0 次 `std::string` 移动构造；
- 只是 `vector` 内部指针转移。

---

### 2.5 计时测试里的拷贝 vs 移动

```cpp
auto v1 = MakeLongStrings(n);
auto v1b = v1;      // 这里已经拷贝了一次 vector<string>，不在计时内

auto t0 = Clock::now();
std::vector<std::string> copied = v1;          // 拷贝 vector<string>
auto t1 = Clock::now();
std::vector<std::string> moved = std::move(v1b); // 移动 vector<string>
auto t2 = Clock::now();
```

计时区里：

- `copied = v1`：`vector<string>` 拷贝构造。
  - 每个 `std::string` 都会被拷贝构造。
  - 字符串长度 64，超过 SSO，内容在堆上。
  - 所以要为每个字符串分配堆内存并复制 64 字节。
  - 这是 O(n) 次深拷贝。

- `moved = std::move(v1b)`：`vector<string>` 移动构造。
  - 只偷 `v1b` 的缓冲区指针。
  - 不调用 `std::string` 的移动构造。
  - 不分配堆内存，不复制字符。
  - 这是 O(1) 指针操作。

所以打印出来的 `copy_us` 通常远大于 `move_us`。

---

### 2.6 `MakeLongStrings` 内部有没有拷贝？

```cpp
std::vector<std::string> MakeLongStrings(size_t n) {
    std::string s = "x";
    for (int i = 1; i <= 6; ++i) s += s; // 1->2->4->8->16->32->64
    std::vector<std::string> vec(n, s);
    return vec;
}
```

这里：

- `s += s` 六次，得到长度 64 的 `"xxxx..."`。
- `std::vector<std::string> vec(n, s);` 会创建 n 个 `std::string`，每个都从 `s` **拷贝构造**。
- 所以这个函数内部有 n 次 `std::string` 拷贝。
- 返回 `vec` 时，通常有 NRVO 或移动构造 `vector`，只偷缓冲区。

但测试里不统计 `MakeLongStrings` 内部的拷贝，它只检查最终内容是否正确。

## 3. 三个自查问题

### ① 为什么 `vector` 的移动不调用任何元素的移动构造？

因为 `vector` 的元素在堆上，`vector` 对象本身只保存：

```cpp
T* begin;
T* end;
T* cap;
```

移动一个 `vector` 时，只需要把这三个指针复制给新 `vector`，然后把源 `vector` 的指针置空。

元素对象还在原来的堆内存地址上，没有搬家，所以不需要调用元素的移动构造。

只有 `vector` 扩容时，才需要把旧缓冲区里的元素搬到新缓冲区，那时才会调用元素的移动构造或拷贝构造。

---

### ② 为什么用 64 个字符而不是 3 个？

因为 `std::string` 有 SSO，小字符串优化。

短字符串，比如 `"xxx"`，内容直接存在 `std::string` 对象内部，不分配堆内存。

拷贝这种短字符串，只是复制对象内部的几个字节，和移动差别不大。

长度 64 超过 SSO 阈值，字符串内容在堆上。

这时：

- 拷贝 `string`：要分配新堆内存，复制 64 字节。
- 移动 `string`：只偷指针。

虽然 `vector` 移动根本不涉及 `string` 移动，但在计时对比 `vector<string>` 拷贝 vs 移动时，拷贝要做 n 次堆分配和深拷贝，移动只偷 `vector` 缓冲区，差异就非常明显。

---

### ③ moved-from 的 `vector` 为什么还能用？

C++ 标准规定：标准库对象被移动后，处于“有效但未指定状态”。

对于 `std::vector`，移动构造后通常为空，但不保证一定是空。它保证：

- 可以安全析构；
- 可以重新赋值；
- 可以 `clear()`；
- 可以 `push_back()`；
- 可以重新使用。

测试里：

```cpp
std::vector<std::string> a = MakeLongStrings(10);
auto b = std::move(a);
a = std::vector<std::string>{"hello"};
```

`a` 被移动后，`b` 拿走了原来的缓冲区。`a` 本身仍然是一个合法的 `vector` 对象，只是不再拥有那些字符串。然后你对 `a` 做移动赋值，它会释放自己当前资源，再接管临时 `vector` 的资源，所以 `a` 又可以正常使用。

---

## 4. 总结成一句话

- `auto copied = src;` → `vector` 拷贝构造 → 每个 `Tracked` 调拷贝构造 → `copies = n`。
- `auto moved = std::move(src);` → `vector` 移动构造 → 只偷指针 → `copies = 0, moves = 0`。
- `auto b = std::move(a);` 对 `vector<string>` 也一样 → 只偷 `vector` 缓冲区，不移动 `string` 元素。
- 计时测试里，拷贝 `vector<string>` 要深拷贝每个长度为 64 的字符串，移动 `vector<string>` 只偷指针，所以移动快得多。
- `std::move` 不是移动，只是右值转换；真正的移动发生在 `vector` 的移动构造/移动赋值里。
