# 模块一：浅拷贝、深拷贝与 Rule of 3 / Rule of 5 / Rule of 0

## 1.1 什么是浅拷贝

浅拷贝：只复制成员的值。如果成员是指针或句柄，就只复制“地址”或“句柄编号”，两个对象仍然指向同一份底层资源。

编译器默认生成的拷贝构造和拷贝赋值，通常就是“逐成员拷贝”。对于裸指针成员，默认拷贝只复制指针地址。

例子：

```cpp
class A {
    int* p;
public:
    A(int v) : p(new int(v)) {}
    ~A() { delete p; }
};
```

如果不写拷贝构造，编译器生成的类似：

```cpp
A(const A& other) : p(other.p) {}  // 只复制指针地址
```

使用：

```cpp
A a(10);
A b = a;   // b.p == a.p，两个对象指向同一块 int
```

此时 `a.p` 和 `b.p` 指向同一内存。析构时两个对象都 `delete p`，导致 double free / 重复释放。

文件句柄也一样：

```cpp
struct File {
    FILE* fp;
    ~File() { if (fp) fclose(fp); }
};
```

浅拷贝后两个对象持有同一个 `FILE*`，析构时都 `fclose`，会重复关闭，行为未定义或出错。

## 1.2 什么是深拷贝

深拷贝：不只复制成员的值，还复制成员所指向或管理的底层资源，让新对象拥有一份独立资源。

对于裸指针：

```cpp
class A {
    int* p;
public:
    A(int v) : p(new int(v)) {}

    A(const A& other) : p(new int(*other.p)) {}  // 新分配内存，复制值

    A& operator=(const A& other) {
        if (this != &other) {
            int* newp = new int(*other.p); // 先分配新的
            delete p;                      // 再释放旧的
            p = newp;
        }
        return *this;
    }

    ~A() { delete p; }
};
```

使用：

```cpp
A a(10);
A b = a;
```

现在 `a.p` 和 `b.p` 指向不同地址，各自独立。修改 `b` 不影响 `a`，析构时各自释放自己的内存，不会重复释放。

对于文件句柄，深拷贝不一定是复制文件内容，而是让新对象获得一个独立的句柄。例如用 `dup()` 复制文件描述符，或者重新 `fopen` / `open`，或者用 `std::shared_ptr` 做共享所有权管理。

关键不是“复制文件内容”，而是：不要让两个对象都以为自己拥有同一个可释放句柄。

## 1.3 浅拷贝与深拷贝对比

| 类型                | 浅拷贝                                       | 深拷贝                             |
| ------------------- | -------------------------------------------- | ---------------------------------- |
| 指针 `int* p`       | 只复制指针地址，两个对象指向同一内存         | 新 `new` 一块内存，复制原内容      |
| 文件句柄 `FILE*`    | 复制指针，两个对象操作同一个 `FILE*`         | 各自 `dup` / `fopen`，拥有独立句柄 |
| 文件描述符 `int fd` | 复制整数 fd，两个对象 close 同一个 fd        | `dup(fd)` 得到新 fd，各自 close    |
| 后果                | 共享资源，容易 double free、重复 close、悬空 | 各自独立，生命周期清楚             |

## 1.4 为什么会有这种问题

编译器默认拷贝是“逐成员拷贝”。如果成员是：

- `int`、`double` 等普通值：没问题；
- `std::string`、`std::vector`：它们自己的拷贝构造会正确复制内容，通常也没问题；
- 裸指针 `T*`、`FILE*`、`int fd` 等资源句柄：默认拷贝就是浅拷贝，通常有问题。

所以：如果你的类需要手写析构函数来释放资源，那么默认拷贝很可能只是浅拷贝。你要么手写拷贝构造和拷贝赋值做深拷贝，要么禁止拷贝，要么用智能指针/容器，让成员自己管理资源。
