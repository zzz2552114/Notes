下面以 **C++ 为主** 讲，最后会提 C 的差异。先给结论：

> **`static` 和 `inline` 不是一对互斥关键字，它们解决的是不同维度的问题。**  
> - `static` 主要控制：**链接性**、**存储期**、**成员归属**。  
> - `inline` 主要控制：**是否允许在多个翻译单元中重复定义相同函数/变量**，以及给编译器一个“可以内联展开”的建议。  
> - 它们可以组合，例如 `static inline`、`inline static`。  
> - 最容易混淆的是：**“内联 inline”不是“内部链接 internal linkage”**。`inline` 函数通常是**外部链接**，而 `static` 全局函数才是**内部链接**。

---

## 1. 基础名词：翻译单元、声明、定义、作用域、存储期、链接性

### 1.1 翻译单元 translation unit

一个 `.cpp` 文件加上它 `#include` 的所有头文件，经过预处理后，形成一个 **翻译单元**。  
编译器把一个翻译单元编译成一个目标文件 `.o/.obj`。  
链接器把多个目标文件链接成一个程序。

所以：
- 一个程序可以有多个翻译单元。
- 一个头文件可能被多个翻译单元包含。
- 同一个名字在不同翻译单元中，是不是同一个东西，由**链接性**决定。

### 1.2 声明 declaration 与定义 definition

```cpp
extern int x;        // 声明：告诉编译器有 x，但没分配存储
int x = 0;           // 定义：分配存储，初始化

int f(int);          // 函数声明
int f(int a) {       // 函数定义
    return a;
}
```

- 声明：名字存在，类型是什么。
- 定义：真正产生实体，比如变量分配空间，函数给出函数体。
- 普通全局变量、普通函数在整个程序中只能定义一次。

### 1.3 作用域 scope

作用域是名字在源代码中**可见的范围**。

常见：
- 块作用域：`{ int x; }`
- 函数作用域：函数参数、标签
- 类作用域：类成员
- 命名空间作用域：全局、命名空间内
- 全局作用域

作用域回答的是：**在这个位置能不能看到这个名字？**

### 1.4 存储期 storage duration

存储期是对象**生命周期**。

常见：
- 自动存储期：局部非 `static` 变量，离开作用域销毁。
- 静态存储期：程序开始到结束一直存在。全局变量、`static` 全局变量、`static` 局部变量、类静态成员。
- 线程存储期：`thread_local`
- 动态存储期：`new/delete`

存储期回答的是：**这个对象活多久？**

### 1.5 链接性 linkage

链接性回答的是：

> 在不同作用域、不同翻译单元中出现的同名声明，是否指代同一个实体？

C++ 中主要有：
- **外部链接 external linkage**
- **内部链接 internal linkage**
- **无链接 no linkage**

## 2. 链接性详解

### 2.1 外部链接 external linkage

名字可以在**其他翻译单元**中被引用。  
典型：

```cpp
int g;                 // 外部链接
void f() {}            // 外部链接
extern int x;          // 声明为外部链接
inline int y = 0;      // C++17 inline 变量，默认外部链接
```

特点：
- 整个程序中只有一个实体。
- 其他 `.cpp` 可以通过声明使用它。
- 普通非 `static` 全局变量、普通函数、类成员函数、类静态数据成员，通常都是外部链接。

### 2.2 内部链接 internal linkage

名字只能在**当前翻译单元**内被引用。其他 `.cpp` 看不到。

典型：

```cpp
static int g;          // 内部链接
static void f() {}     // 内部链接

namespace {
    int x;             // 匿名命名空间，内部链接
}

const int c = 1;       // C++ 中命名空间作用域 const 变量默认内部链接
constexpr int d = 2;   // C++ 中 constexpr 变量默认内部链接，除非 extern/inline
```

特点：
- 每个翻译单元可以有一份自己的实体。
- 不同 `.cpp` 中同名的 `static` 全局变量是不同对象。
- 地址通常不同。
- 不会和别的翻译单元的符号冲突。

### 2.3 无链接 no linkage

名字只在当前作用域有效，不能跨作用域或翻译单元指代同一实体。

典型：

```cpp
void f() {
    int x;             // 无链接，自动存储期
    static int y;      // 无链接，静态存储期
}
```

注意：`static` 局部变量虽然叫 `static`，但它**没有链接性**。它只是有静态存储期。

### 2.4 链接性、作用域、存储期三者不是一回事

例子：

```cpp
void f() {
    static int x = 0;
}
```

- 作用域：块作用域，只在 `f` 内可见。
- 存储期：静态存储期，程序结束才销毁。
- 链接性：无链接。

再如：

```cpp
static int g = 0;  // 命名空间作用域
```

- 作用域：当前翻译单元。
- 存储期：静态存储期。
- 链接性：内部链接。

## 3. `static` 是什么？它有好几种完全不同的含义

`static` 在 C++ 中非常“重载”，不同位置含义不同。

### 3.1 命名空间作用域的 `static`：控制内部链接

```cpp
static int g = 0;        // 内部链接
static void f() {}       // 内部链接
```

含义：
- 这个变量/函数只属于当前 `.cpp`。
- 其他翻译单元不能引用它。
- 每个包含该声明的翻译单元会得到自己的实体。
- 如果写在头文件里，每个包含该头文件的 `.cpp` 都会有一份自己的副本。

C++ 中更推荐用匿名命名空间替代 `static` 全局：

```cpp
namespace {
    int g = 0;
    void f() {}
}
```

匿名命名空间里的名字也是内部链接，而且还能放类型、模板等，`static` 只能用于变量和函数。

### 3.2 块作用域的 `static`：控制静态存储期

```cpp
void f() {
    static int count = 0;
    ++count;
}
```

含义：
- 作用域仍然是块作用域，只在 `f` 内可见。
- 链接性：无链接。
- 存储期：静态存储期。
- 只初始化一次，C++11 起初始化线程安全。
- 每次调用 `f`，`count` 保持上次的值。

它和“内部链接”无关。

### 3.3 类作用域的 `static`：表示静态成员

```cpp
struct A {
    static int x;          // 静态数据成员声明
    static void f();       // 静态成员函数
};

int A::x = 0;              // 定义，通常外部链接
void A::f() {}
```

含义：
- 静态数据成员属于类，不属于某个对象。
- 所有 `A` 的对象共享同一个 `A::x`。
- 静态成员函数没有 `this` 指针，可以直接用 `A::f()` 调用。
- 静态数据成员通常有外部链接，整个程序一个实体。
- C++17 之前，静态数据成员需要在类外定义。
- C++17 起可以：

```cpp
struct A {
    inline static int x = 0;   // 类内定义，外部链接，一个实体
};
```

### 3.4 `static` 总结表

| 位置               | 作用                   | 链接性       | 存储期 |
| ------------------ | ---------------------- | ------------ | ------ |
| 命名空间作用域变量 | 限制本翻译单元         | 内部链接     | 静态   |
| 命名空间作用域函数 | 限制本翻译单元         | 内部链接     | —      |
| 块作用域变量       | 只初始化一次，长期存在 | 无链接       | 静态   |
| 类静态数据成员     | 属于类，所有对象共享   | 通常外部链接 | 静态   |
| 类静态成员函数     | 属于类，无 `this`      | 通常外部链接 | —      |

## 4. `inline` 是什么？

`inline` 有两个层面：

1. **语言语义层面**：允许函数/变量在多个翻译单元中重复定义相同版本，不违反 ODR。
2. **优化层面**：建议编译器把函数调用展开成函数体。但这只是建议，现代编译器自己决定。

### 4.1 内联函数 inline function

```cpp
inline int add(int a, int b) {
    return a + b;
}
```

关键点：
- `inline` 函数默认是**外部链接**。
- 可以在多个翻译单元中出现相同定义。
- 链接器会把它们合并成一个实体。
- 所有翻译单元中的定义必须完全相同，否则未定义行为。
- `inline` 不保证一定展开。递归、取地址、调试模式等都可能不展开。
- 类内定义的成员函数隐式是 `inline`。

```cpp
struct A {
    void f() {}   // 隐式 inline
};
```

`constexpr` 函数也隐式 `inline`。

### 4.2 内联变量 inline variable，C++17

```cpp
inline int global = 0;
```

含义：
- 允许在多个翻译单元中定义相同变量。
- 整个程序只有一个实体。
- 默认外部链接，除非加 `static`。
- 常用于头文件中定义全局变量或类静态成员。

C++17 之前，头文件里写：

```cpp
int global = 0;   // 多个 .cpp 包含会多重定义
```

C++17 后可以：

```cpp
inline int global = 0;   // 多个 .cpp 包含 OK，一个实体
```

### 4.3 隐式 inline

以下情况是隐式 `inline`：
- 类内定义的成员函数。
- `constexpr` 函数。
- C++17 起，`static constexpr` 数据成员隐式 `inline`。
- C++17 起，类内 `inline static` 数据成员。

### 4.4 内联展开不是强制的

```cpp
inline int f() { return 1; }
```

编译器可能：
- 在调用点直接替换成 `1`；
- 也可能仍然生成函数调用；
- 也可能既生成函数体又展开。

`inline` 关键字的主要现代意义是：**允许头文件中多翻译单元定义同一个函数/变量**。

## 5. `inline` 和 `static` 的关系

核心一句话：

> `static` 管“这个名字/实体是不是只在本翻译单元内”；  
> `inline` 管“这个函数/变量能不能在多个翻译单元里重复定义相同版本，以及是否建议展开”。  
> 它们是不同维度，可以同时出现。

### 5.1 普通函数

```cpp
void f() {}          // 外部链接，只能定义一次
```

### 5.2 `static` 函数

```cpp
static void f() {}   // 内部链接，每个翻译单元一份
```

### 5.3 `inline` 函数

```cpp
inline void f() {}   // 外部链接，多翻译单元可定义相同，链接器合并为一个
```

### 5.4 `static inline` 函数

```cpp
static inline void f() {}  // 内部链接 + 建议内联
```

含义：
- `static` 使它内部链接。
- 每个翻译单元有自己的 `f`。
- `inline` 仍然表示建议内联，并且允许重复定义不冲突。
- 在 C 中，`static inline` 常用于头文件。
- 在 C++ 中也可以，但如果你希望所有翻译单元共享同一个函数实体，应该用 `inline` 而不是 `static inline`。

### 5.5 变量对比

| 写法                          | 链接性       | 多翻译单元定义     | 实体数       |
| ----------------------------- | ------------ | ------------------ | ------------ |
| `int g;`                      | 外部链接     | 只能一个定义       | 一个         |
| `static int g;`               | 内部链接     | 每个 TU 可有一个   | 每个 TU 一个 |
| `inline int g = 0;`           | 外部链接     | 多个 TU 可相同定义 | 一个         |
| `static inline int g = 0;`    | 内部链接     | 每个 TU 可有一个   | 每个 TU 一个 |
| 局部 `static int x;`          | 无链接       | 不跨 TU            | 每个函数一个 |
| 类 `static int x;`            | 通常外部链接 | 只能一个定义       | 一个         |
| 类 `inline static int x = 0;` | 通常外部链接 | 多 TU 可相同定义   | 一个         |

### 5.6 类中的 `inline static`

```cpp
struct A {
    inline static int x = 0;   // C++17
};
```

这里：
- `static`：表示 `x` 是静态数据成员，属于类。
- `inline`：允许在类内直接定义，并且多个翻译单元包含该头文件时只有一个实体。
- 链接性：通常外部链接。
- 所有 `A` 对象共享 `A::x`。

## 6. 具体例子

### 6.1 头文件中的函数

```cpp
// common.h
#pragma once

inline int add(int a, int b) {
    return a + b;
}

static int sub(int a, int b) {
    return a - b;
}
```

在 `a.cpp` 和 `b.cpp` 都包含：

- `add`：外部链接，多翻译单元定义相同，链接器合并成一个。
- `sub`：内部链接，`a.cpp` 和 `b.cpp` 各有一份自己的 `sub`，地址不同，状态不共享。

### 6.2 头文件中的变量

```cpp
// common.h
#pragma once

inline int global = 0;   // C++17
static int counter = 0;
```

- `global`：所有翻译单元共享同一个变量。
- `counter`：每个翻译单元各有一份，互不影响。

### 6.3 局部 static

```cpp
void f() {
    static int count = 0;
    ++count;
}
```

- 无链接。
- 静态存储期。
- 只初始化一次。
- 每次调用 `f` 都使用同一个 `count`。

### 6.4 类静态成员

```cpp
struct A {
    static int x;              // 声明
    inline static int y = 0;   // C++17 定义
    static constexpr int z = 1; // C++17 隐式 inline
};

int A::x = 0;                  // 定义
```

- `A::x`：一个实体，所有对象共享。
- `A::y`：一个实体，类内定义。
- `A::z`：一个实体，隐式 inline。

## 7. 常见误区

### 误区 1：`inline` 就是内部链接

错。  
`inline` 函数默认是**外部链接**。  
内部链接是 `static` 或匿名命名空间。

### 误区 2：`static` 一定是内部链接

不一定。
- 命名空间作用域 `static`：内部链接。
- 块作用域 `static`：无链接，静态存储期。
- 类静态成员：通常外部链接。

### 误区 3：`static` 全局变量和 `static` 局部变量一样

不一样。
- `static` 全局变量：内部链接。
- `static` 局部变量：无链接，静态存储期。

### 误区 4：`inline` 一定会展开

不一定。  
`inline` 只是建议，编译器可以忽略。  
现代编译器经常自己决定内联，甚至内联没有 `inline` 的函数。

### 误区 5：头文件里写 `static` 函数就万事大吉

可以避免链接冲突，但：
- 每个翻译单元一份副本，代码膨胀。
- 不同翻译单元中的函数地址不同。
- 如果函数里有 `static` 局部变量，每个翻译单元一份，不共享。
- 如果希望全程序一个实体，应该用 `inline`。

### 误区 6：`const` 全局变量在 C++ 中默认外部链接

错。  
C++ 中命名空间作用域 `const int x = 1;` 默认是**内部链接**。  
如果需要外部链接，要写：

```cpp
extern const int x = 1;
```

或者 C++17：

```cpp
inline const int x = 1;
```

## 8. C 和 C++ 的差异

如果你写的是 C：

- C 中 `const` 全局变量默认是**外部链接**，和 C++ 不同。
- C 没有匿名命名空间、类、`inline` 变量。
- C99 的 `inline` 语义和 C++ 不同，C 中头文件里常用：

```c
static inline int add(int a, int b) {
    return a + b;
}
```

- C 中 `static` 全局函数/变量也是内部链接。
- C 中 `static` 局部变量也是静态存储期、无链接。

## 9. 最终总结

| 名词                   | 含义                                                  |
| ---------------------- | ----------------------------------------------------- |
| 链接性 linkage         | 同名声明是否指代同一实体，能否跨翻译单元引用          |
| 外部链接               | 整个程序可见，其他翻译单元可引用                      |
| 内部链接               | 仅当前翻译单元可见                                    |
| 无链接                 | 仅当前作用域可见                                      |
| 内联 inline            | 语言上允许多翻译单元定义相同函数/变量；优化上建议展开 |
| `static` 全局          | 内部链接                                              |
| `static` 局部          | 无链接，静态存储期                                    |
| `static` 类成员        | 属于类，所有对象共享，通常外部链接                    |
| `inline` 函数          | 默认外部链接，多翻译单元相同定义可合并为一个          |
| `static inline` 函数   | 内部链接 + 内联建议，每个翻译单元一份                 |
| `inline static` 类成员 | 静态成员 + 类内定义，通常外部链接，一个实体           |

一句话再强调：

> **`static` 和 `inline` 没有必然对立关系。`static` 常常决定“只在本文件可见”，`inline` 决定“多个文件可以出现相同定义并合并/建议展开”。`inline` 函数默认外部链接，`static` 函数才是内部链接。两者可以组合，但含义要分位置看。**
