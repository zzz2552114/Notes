# C/C++ 复杂声明解析笔记

## 0. 一句话总纲

> **复杂声明从变量名出发读：先向右看，再向左看；遇到括号先处理括号里面；`[]` 和 `()` 的优先级高于 `*` 和 `&`；`const` 不是运算符，没有优先级，它按位置修饰类型。**

最核心的心法：

> **声明模仿使用。**  
> 声明写成什么样，就暗示你以后在表达式里怎么用它。

---

# 1. 核心解析规则：右左规则

## 1.1 规则

从变量名开始：

1. 先向右看；
2. 再向左看；
3. 遇到括号，先处理括号里面；
4. 右边看到 `[N]`：读作“数组，N 个元素”；
5. 右边看到 `(参数)`：读作“函数，返回”；
6. 左边看到 `*`：读作“指针，指向”；
7. 左边看到 `&`：读作“引用”；
8. 最后看最左边的基类型，如 `int`、`const int`。

## 1.2 真正有优先级的是谁？

有优先级和结合性的是声明符：

```cpp
[]   和   ()   高于   *   和   &
```

`const` 不是运算符，没有“优先级”和“结合性”。  
它只是类型限定符，修饰谁取决于它在声明里的位置。

# 2. 最重要的一组：指针和数组

## 2.1 `int *p[4];`

```cpp
int *p[4];
```

因为 `[]` 优先级高于 `*`，所以它等价于：

```cpp
int *(p[4]);
```

从 `p` 开始解析：

1. 右边 `[4]`：`p` 是数组，有 4 个元素；
2. 左边 `*`：数组元素是指针；
3. 最左边 `int`：指针指向 `int`。

所以：

```cpp
p 是数组，有 4 个元素，每个元素是 int*
```

类型写作：

```cpp
int *[4]
```

这叫：**指针数组**。

### 关键卡点：为什么外面的 `*` 表示“数组元素是指针”？

因为：

```cpp
int *p[4];
```

等价于：

```cpp
int *(p[4]);
```

这里的 `*` 修饰的是 `(p[4])` 这个整体。  
而 `p[4]` 在声明中代表“数组元素的位置”。  
所以：

> `*` 戴在 `p[4]` 头上，表示数组元素是指针。

用“帽子比喻”：

```cpp
int * (p[4])
     ↑   ↑
   帽子  数组元素
```

帽子戴在数组元素上，不是戴在 `p` 上。

---

## 2.2 `int (*p)[4];`

```cpp
int (*p)[4];
```

括号强制 `*` 先和 `p` 结合。

从 `p` 开始：

1. 右边是 `)`，先看括号里面；
2. 括号里是 `*p`：`p` 是指针；
3. 出括号，右边 `[4]`：`p` 指向一个数组，有 4 个元素；
4. 最左边 `int`：数组元素是 `int`。

所以：

```cpp
p 是指针，指向一个 int[4] 数组
```

类型写作：

```cpp
int (*)[4]
```

这叫：**数组指针**。

### 用实际使用反推

```cpp
(*p)[0] = 10;
```

`(*p)[0]` 是 `int`，所以：

```cpp
*p 是数组，元素是 int
```

所以：

```cpp
p 是指向 int[4] 的指针
```

---

## 2.3 对比表

| 声明           | `p` 的类型   | 含义                                    |
| -------------- | ------------ | --------------------------------------- |
| `int *p[4];`   | `int *[4]`   | `p` 是数组，4 个元素，每个元素是 `int*` |
| `int (*p)[4];` | `int (*)[4]` | `p` 是指针，指向 `int[4]`               |
| `int *p;`      | `int*`       | `p` 是指向 `int` 的指针                 |
| `int p[4];`    | `int[4]`     | `p` 是 4 个 `int` 的数组                |

一句话：

```cpp
int *p[4];    // 指针数组：数组里放指针
int (*p)[4];  // 数组指针：指针指向数组
```

# 4. 把 `*` 换成 `&` 会怎样？

解析规则不变，但语义合法性变了。

C++ 有一条硬规则：

> **不能有“引用的数组”，但可以有“数组的引用”。**

## 4.1 `int &p[4];` 非法

```cpp
int &p[4];
```

因为 `[]` 优先级高于 `&`，等价于：

```cpp
int &(p[4]);
```

解析结果：

> `p` 是数组，有 4 个元素，每个元素是 `int&`。

也就是：

```cpp
int &[4]
```

但 C++ 禁止引用数组，因为引用不是对象，不能像普通对象一样被放进数组元素里。

所以：

```cpp
int &p[4];   // 非法：引用数组
```

## 4.2 `int (&p)[4];` 合法

```cpp
int (&p)[4];
```

括号强制 `&` 先和 `p` 结合。

从 `p` 开始：

1. 右边是 `)`，先看括号里面；
2. 括号里 `&p`：`p` 是引用；
3. 出括号，右边 `[4]`：引用的是一个数组，有 4 个元素；
4. 最左边 `int`：数组元素是 `int`。

所以：

```cpp
p 是引用，引用一个 int[4] 数组
```

类型写作：

```cpp
int (&)[4]
```

这是合法的，但引用必须初始化：

```cpp
int a[4];
int (&p)[4] = a;
p[0] = 10;  // 等价于 a[0] = 10
```

## 4.3 对比表

| 声明           | 解析结果                  | 是否合法 | 含义                 |
| -------------- | ------------------------- | -------- | -------------------- |
| `int *p[4];`   | `p` 是数组，元素是 `int*` | 合法     | 指针数组             |
| `int (*p)[4];` | `p` 是指针，指向 `int[4]` | 合法     | 数组指针             |
| `int &p[4];`   | `p` 是数组，元素是 `int&` | **非法** | 引用数组，C++ 不允许 |
| `int (&p)[4];` | `p` 是引用，引用 `int[4]` | 合法     | 数组引用             |

# 5. 模板为什么能用 `T (&arr)[N]` 推导数组长度？

## 5.1 普通数组参数会退化

```cpp
template <class T, std::size_t N>
void g(T arr[N]);
```

函数参数如果是数组类型，会自动调整为指针类型。  
所以它实际等价于：

```cpp
template <class T, std::size_t N>
void g(T* arr);
```

调用：

```cpp
int a[5];
g(a);
```

数组 `a` 退化为 `int*`，长度 `5` 丢失。  
所以 `N` 无法推导。

## 5.2 数组引用不会退化

```cpp
template <class T, std::size_t N>
void f(T (&arr)[N]);
```

这里 `arr` 不是数组参数，而是：

```cpp
T (&)[N]
```

意思是：

> `arr` 是一个引用，引用一个类型为 `T[N]` 的数组。

调用：

```cpp
int a[5];
f(a);
```

实参 `a` 的类型是：

```cpp
int[5]
```

形参模式是：

```cpp
T (&)[N]
```

也就是“引用到 `T[N]` 数组”。

模板推导就是模式匹配：

```text
形参模式：T[N]
实参类型：int[5]
```

于是：

```cpp
T = int
N = 5
```

## 5.3 为什么不退化？三个原因

1. 形参是**数组引用**，不是数组参数；
2. 绑定引用时，不发生数组到指针转换；
3. 函数参数调整规则不适用于引用类型。

所以实参数组保持完整类型 `int[5]`。  
数组类型里带着长度，所以 `N` 能被推导出来。

## 5.4 代码证明

```cpp
#include <iostream>
#include <cstddef>

template <class T, std::size_t N>
void f(T (&arr)[N]) {
    std::cout << "N = " << N << '\n';
    std::cout << "sizeof(arr) = " << sizeof(arr) << '\n';
}

int main() {
    int a[5];
    f(a);
}
```

输出：

```text
N = 5
sizeof(arr) = 20
```

如果 `arr` 退化成指针，`sizeof(arr)` 通常是指针大小，比如 8。  
这里输出 20，说明 `arr` 仍代表整个 `int[5]` 数组。

## 5.5 对比表

| 形参写法      | 实际形参类型 | 数组实参是否退化 | 推导结果              |
| ------------- | ------------ | ---------------- | --------------------- |
| `T arr[N]`    | `T*`         | 是               | `T=int`，`N` 无法推导 |
| `T* arr`      | `T*`         | 是               | `T=int`               |
| `T& arr`      | `T&`         | 否               | `T=int[5]`            |
| `T (&arr)[N]` | `T (&)[N]`   | 否               | `T=int, N=5`          |

一句话：

> **引用让数组保持原样，不退化；数组类型里带着长度，所以 `N` 能被推导出来。**

# 6. `const` 到底修饰谁？

## 6.1 `const` 不是运算符

`const` 没有优先级和结合性。  
真正有优先级的是：

```cpp
[] 和 () 高于 * 和 &
```

`const` 是类型限定符，按位置修饰类型。

常用直觉：

- `const` 在 `*` 左边：修饰指针指向的东西；
- `const` 在 `*` 右边：修饰指针本身；
- 两边都有：指向的东西和指针本身都 const。

但遇到数组声明，还要先看 `[]`、`()`、`*` 的结合。

---

## 6.2 `const int* p[10];`

```cpp
const int* p[10];
```

因为 `[]` 优先级高于 `*`，等价于：

```cpp
const int *(p[10]);
```

从 `p` 开始：

1. 右边 `[10]`：`p` 是数组，有 10 个元素；
2. 左边 `*`：数组元素是指针；
3. 左边 `const int`：指针指向 `const int`。

所以：

```cpp
p 是数组，有 10 个元素，每个元素是 const int*
```

类型写作：

```cpp
const int *[10]
```

这里 `const` 修饰的是 `int`，不是 `p`，也不是指针本身。

含义：

- `p[0]` 是指针，指针本身不是 const，可以改指向；
- `*p[0]` 是 `const int`，不能通过它改值。

例子：

```cpp
const int a = 1, b = 2;
const int* p[10];

p[0] = &a;   // 可以：改指针指向
p[1] = &b;   // 可以
// *p[0] = 3; // 错误：不能改 const int
```

---

## 6.3 `const int (*p)[10];`

```cpp
const int (*p)[10];
```

从 `p` 开始：

1. 右边是 `)`，先看括号里面；
2. 括号里 `*p`：`p` 是指针；
3. 出括号，右边 `[10]`：`p` 指向一个数组，有 10 个元素；
4. 最左边 `const int`：数组元素是 `const int`。

所以：

```cpp
p 是指针，指向一个 const int[10] 数组
```

类型写作：

```cpp
const int (*)[10]
```

这里 `const` 修饰的是 `int`，也就是数组元素。  
`p` 本身不是 `const`。

含义：

- `p` 可以改指向；
- `(*p)[i]` 是 `const int`，不能改值。

例子：

```cpp
const int a[10] = {};
const int b[10] = {};

const int (*p)[10] = &a;

p = &b;          // 可以：p 本身不是 const
// (*p)[0] = 1;  // 错误：元素是 const int
```

---

## 6.4 容易混的几个 `const` 声明

| 声明                         | `p` 是什么                       | `const` 修饰谁                   |
| ---------------------------- | -------------------------------- | -------------------------------- |
| `const int* p[10];`          | 数组，元素是 `const int*`        | 修饰 `int`，即指针指向的 int     |
| `const int (*p)[10];`        | 指针，指向 `const int[10]`       | 修饰 `int`，即数组元素           |
| `int* const p[10];`          | 数组，元素是 `int* const`        | 修饰指针，即数组元素指针本身     |
| `int (* const p)[10];`       | const 指针，指向 `int[10]`       | 修饰 `p`，即指针本身             |
| `const int (* const p)[10];` | const 指针，指向 `const int[10]` | 第一个修饰 `int`，第二个修饰 `p` |

特别注意：

```cpp
int* const p[10];
```

解析为：

> `p` 是数组，元素是 `int* const`。  
> 数组里的每个指针本身是 const，不能改指向，但可以通过它改 `int` 值。

而：

```cpp
int (* const p)[10];
```

解析为：

> `p` 是 const 指针，指向 `int[10]`。  
> `p` 不能改指向，但它指向的数组元素是普通 `int`，可以通过 `(*p)[i]` 修改。

# 7. 通用速查口诀

## 7.1 解析复杂声明

> 从变量名出发：先右后左，遇括号先内后外。  
> 右 `[N]`：数组 N 个元素。  
> 右 `(参数)`：函数。  
> 左 `*`：指针，指向。  
> 左 `&`：引用。  
> 最后加基类型。

## 7.2 指针和数组

```cpp
int *p[4];    // p 是数组，元素是 int*
int (*p)[4];  // p 是指针，指向 int[4]
```

## 7.3 引用和数组

```cpp
int &p[4];    // 非法：引用数组
int (&p)[4];  // 合法：数组引用，必须初始化
```

## 7.4 模板推数组长度

```cpp
template <class T, std::size_t N>
void f(T (&arr)[N]);  // 数组引用不退化，可推 N
```

普通 `T arr[N]` 会退化为 `T*`，长度丢失。

## 7.5 `const`

- `const` 不是运算符，没有优先级；
- `[]` 和 `()` 高于 `*` 和 `&`；
- `const` 在 `*` 左边通常修饰指向物；
- `const` 在 `*` 右边通常修饰指针本身；
- 遇到数组声明，先看 `[]`、`()`、`*` 怎么结合，再判断 `const` 修饰谁。

# 8. 常见误区清单

1. **误区：`int *` 永远是一个整体。**  
   不是。`int` 只是基类型，`*` 在声明符里表示指针层级。  
   `int *p[4]` 里 `*` 修饰的是 `p[4]` 这个数组元素位置。

2. **误区：`int *p[4]` 表示 `p` 是指针。**  
   错。`p` 是数组，元素是 `int*`。

3. **误区：`int (*p)[4]` 和 `int *p[4]` 差不多。**  
   完全相反：一个是数组指针，一个是指针数组。

4. **误区：`int &p[4]` 是数组引用。**  
   错。它是“引用数组”，非法。数组引用要写 `int (&p)[4]`。

5. **误区：数组参数和数组引用一样。**  
   不一样。数组参数会退化为指针；数组引用不会退化。

6. **误区：`const` 有优先级。**  
   `const` 没有优先级，它按位置修饰类型。真正有优先级的是 `[]`、`()`、`*`、`&`。

7. **误区：`const int* p[10]` 中 `p` 是 const。**  
   不是。`p` 是数组，元素是 `const int*`。`const` 修饰的是 `int`。

8. **误区：`const int (*p)[10]` 中 `p` 是 const。**  
   不是。`p` 是指针，指向 `const int[10]`。`const` 修饰数组元素。  
   要让 `p` 本身 const，要写 `const int (* const p)[10]`。

# 9. 最终记忆卡

```cpp
int *p[4];              // p 是数组，元素是 int*
int (*p)[4];            // p 是指针，指向 int[4]

int &p[4];              // 非法：引用数组
int (&p)[4];            // p 是引用，引用 int[4]

const int* p[10];       // p 是数组，元素是 const int*
const int (*p)[10];     // p 是指针，指向 const int[10]

int* const p[10];       // p 是数组，元素是 int* const
int (* const p)[10];    // p 是 const 指针，指向 int[10]
const int (* const p)[10]; // p 是 const 指针，指向 const int[10]
```

终极一句话：

> **从变量名出发，先右后左，括号优先；`[]`/`()` 高于 `*`/`&`；`*` 是“指针帽子”，戴在谁头上谁就是指针；`&` 是“引用绑定”，不能做数组元素但能引用整个数组；`const` 按位置修饰类型，没有优先级；数组引用不退化，所以模板能推出长度。**
