C语言中确实同时存在 `fread`/`fwrite` 和 `read`/`write`，但它们分属**两套完全不同的文件I/O体系**。下面分别详细介绍。

---

## 📖 一、fread / fwrite（C标准库函数）

`fread` 和 `fwrite` 属于 **C标准输入输出库（`<stdio.h>`）**，是基于 **`FILE*` 文件指针** 的带缓冲I/O函数，主要用于**二进制文件**的批量读写。

### 1. fread — 从流中读取数据块

**函数原型**：
```c
size_t fread(void *ptr, size_t size, size_t nmemb, FILE *stream);
```


**参数说明**：

| 参数     | 含义                               |
| -------- | ---------------------------------- |
| `ptr`    | 指向用于接收数据的内存缓冲区的指针 |
| `size`   | 每个数据项的字节数                 |
| `nmemb`  | 要读取的数据项个数                 |
| `stream` | 指向 `FILE` 结构的指针，指定输入流 |

**返回值**：
- 成功时返回**实际读取的完整数据项个数**（可能小于 `nmemb`）
- 如果发生错误或读到文件末尾，返回值会小于 `nmemb`，甚至为 0
- 若 `size` 或 `nmemb` 为 0，返回 0，且缓冲区内容不变

**关键注意事项**：
- `fread` **无法区分**是“读到文件末尾”还是“发生错误”，必须配合 `feof()` 和 `ferror()` 来判断
- 如果 `stream` 或 `ptr` 是空指针，行为未定义；在部分实现中会设置 `errno` 为 `EINVAL` 并返回 0

**示例**：读取一个结构体数组
```c
#include <stdio.h>

typedef struct {
    int id;
    char name[20];
} Record;

int main() {
    FILE *fp = fopen("data.bin", "rb");
    if (!fp) return 1;

    Record records[10];
    size_t n = fread(records, sizeof(Record), 10, fp);
    printf("实际读取了 %zu 条记录\n", n);

    fclose(fp);
    return 0;
}
```

---

### 2. fwrite — 向流中写入数据块

**函数原型**：
```c
size_t fwrite(const void *ptr, size_t size, size_t nmemb, FILE *stream);
```


**参数说明**：

| 参数     | 含义                               |
| -------- | ---------------------------------- |
| `ptr`    | 指向要写入的数据的指针             |
| `size`   | 每个数据项的字节数                 |
| `nmemb`  | 要写入的数据项个数                 |
| `stream` | 指向 `FILE` 结构的指针，指定输出流 |

**返回值**：
- 成功时返回**实际写入的完整数据项个数**
- 如果该值小于 `nmemb`，表示发生了错误

**关键注意事项**：
- `fwrite` 以**二进制形式**操作文件，不限于文本
- 写入的数据先进入用户空间缓冲区，**不会立即同步到磁盘**；需要调用 `fflush()` 强制刷新
- 如果以文本模式打开流，每个换行符会被替换为回车换行对，但这**不影响返回值**

**示例**：写入结构体
```c
#include <stdio.h>

typedef struct {
    int id;
    char name[20];
} Record;

int main() {
    FILE *fp = fopen("data.bin", "wb");
    if (!fp) return 1;

    Record r = {1, "Alice"};
    size_t n = fwrite(&r, sizeof(Record), 1, fp);
    printf("写入了 %zu 条记录\n", n);

    fflush(fp);   // 确保数据写入磁盘
    fclose(fp);
    return 0;
}
```

## 🔧 二、read / write（POSIX系统调用）

**存在**。`read` 和 `write` 是 **POSIX标准** 定义的**系统调用**，属于**低级I/O**，基于**文件描述符（`int fd`）**，**不带用户空间缓冲**。

### 1. read — 从文件描述符读取字节

**函数原型**：
```c
#include <unistd.h>
ssize_t read(int fd, void *buf, size_t count);
```


**参数说明**：

| 参数    | 含义                 |
| ------- | -------------------- |
| `fd`    | 文件描述符           |
| `buf`   | 存放读取数据的缓冲区 |
| `count` | 请求读取的字节数     |

**返回值**：
- 成功时返回**实际读取的字节数**
- 返回 0 表示**已到达文件末尾**
- 返回 -1 表示出错，并设置 `errno`

**特点**：
- **无用户空间缓冲**，每次调用都直接陷入内核
- 需要自己管理缓冲区大小
- 读写的是**原始字节**，不涉及任何格式转换

**示例**：读取文件前 100 字节
```c
#include <fcntl.h>
#include <unistd.h>
#include <stdio.h>

int main() {
    int fd = open("file.txt", O_RDONLY);
    if (fd == -1) return 1;

    char buf[100];
    ssize_t n = read(fd, buf, sizeof(buf));
    if (n > 0) {
        printf("读取了 %zd 字节\n", n);
    }

    close(fd);
    return 0;
}
```

---

### 2. write — 向文件描述符写入字节

**函数原型**：
```c
#include <unistd.h>
ssize_t write(int fd, const void *buf, size_t count);
```


**参数说明**：

| 参数    | 含义               |
| ------- | ------------------ |
| `fd`    | 文件描述符         |
| `buf`   | 要写入的数据缓冲区 |
| `count` | 请求写入的字节数   |

**返回值**：
- 成功时返回**实际写入的字节数**
- 返回 -1 表示出错，并设置 `errno`

**特点**：
- 同样**无用户空间缓冲**，直接写入内核缓冲区
- 写入的字节数可能小于 `count`（例如磁盘满或信号中断），需要循环写入以确保全部数据写出

**示例**：向文件写入字符串
```c
#include <fcntl.h>
#include <unistd.h>
#include <string.h>

int main() {
    int fd = open("output.txt", O_WRONLY | O_CREAT | O_TRUNC, 0644);
    if (fd == -1) return 1;

    const char *msg = "Hello, system call!";
    ssize_t n = write(fd, msg, strlen(msg));
    printf("写入了 %zd 字节\n", n);

    close(fd);
    return 0;
}
```

## ⚖️ 三、核心区别对比

| 维度           | `fread` / `fwrite`                         | `read` / `write`                                   |
| -------------- | ------------------------------------------ | -------------------------------------------------- |
| **所属标准**   | C标准库（`<stdio.h>`）                     | POSIX系统调用（`<unistd.h>`）                      |
| **操作对象**   | `FILE*` 文件指针                           | `int` 文件描述符                                   |
| **缓冲机制**   | **用户空间带缓冲**，减少系统调用次数       | **无用户空间缓冲**，每次调用直接进入内核           |
| **可移植性**   | 跨平台，ANSI C标准                         | 依赖Unix/Linux系统，Windows下不可直接使用          |
| **适用场景**   | 普通文件的批量二进制读写，尤其是结构体数组 | 设备文件、管道、套接字等需要低延迟或精细控制的场景 |
| **打开方式**   | `fopen()`                                  | `open()`                                           |
| **关闭方式**   | `fclose()`                                 | `close()`                                          |
| **返回值单位** | 成功读取/写入的**项数**                    | 成功读取/写入的**字节数**                          |

**本质关系**：`fread`/`fwrite` **内部最终会调用 `read`/`write`** 来完成实际的数据传输，只是在用户空间增加了一层缓冲来提升效率。

---

## 💎 总结

- **`fread` / `fwrite`** 是C标准库函数，带缓冲，适合**普通文件的批量二进制读写**，跨平台，使用 `FILE*`。
- **`read` / `write`** 是POSIX系统调用，无用户空间缓冲，适合**设备文件、管道、套接字**等场景，使用文件描述符，平台相关。
- 二者**不是替代关系**，而是不同层次的I/O接口，根据具体需求选择即可。

你这段代码里用的其实是标准库函数 **`fread` / `fwrite`**，不是系统调用 `read` / `write`。它不会“截断”，是因为你写了 `while` 循环，让程序**一个字节一个字节地一直读到文件结束（EOF）为止**。下面详细解释。



---

## 1. 这段代码在做什么？

```c
char c;
while(read(0, &c, 1) != 0)
    write(1, &c, 1);
```

- `read`：从标准输入 `stdin` 中尝试读取 **1 个字节**，放到 `c` 里。
- `while(... != 0)`：只要还能读到字节，就继续循环。
- `write`：把刚读到的这 1 个字节写到标准输出 `stdout`。

所以程序本质是一个**逐字节复制**：从 `stdin` 复制到 `stdout`，直到遇到 EOF。

---

## 2. 为什么输入多个字符不会被“截断”？

因为 `read` 本身**不认识行、空格、换行**，它只把输入看成一串字节流。

你每次调用 `read` 只请求 1 个字节，它就读 1 个字节。读完后循环条件仍为真，于是再次调用 `read` 读下一个字节……如此反复，直到没有字节可读（EOF）。

例如你输入：

```text
hello world
```

终端最终会把这一整行（包括最后的换行符 `\n`）交给程序。程序会依次：

```text
读 'h' → 写 'h'
读 'e' → 写 'e'
读 'l' → 写 'l'
读 'l' → 写 'l'
读 'o' → 写 'o'
读 ' ' → 写 ' '
读 'w' → 写 'w'
...
读 '\n' → 写 '\n'
```

然后再次调用 `fread` 等待新输入。所以它不会因为遇到空格或换行就停止，而是**原样复制所有字节**。

---

## 3. 为什么感觉“任由我输入”，然后“原样返回”？

这涉及**终端行缓冲**和**终端回显**。

### 终端行缓冲
当你在交互式终端里输入时，终端驱动通常工作在**行缓冲模式**：
- 你按下的字符不会立刻送给程序，而是先由终端驱动缓存。
- 直到你按下 **回车键**，终端才把这一整行（包括换行符 `\n`）送到程序的 `stdin`。
- 所以程序在你按回车之前，`fread` 一直阻塞等待。

程序收到这一行后，就会逐字节读取并输出。处理完当前行后，再次调用 `fread` 时，如果没有新输入，它又阻塞等待。所以你感觉它可以一直输入，输入多少它就处理多少。

### 终端回显
在终端里，你输入的字符通常会被终端驱动**自动回显**到屏幕上——这是终端本身的行为，不是程序做的。然后程序又把读到的字节写到 `stdout`，`stdout` 也连接到终端，于是又显示一遍。所以有时你会看到字符好像出现了两次，或者看起来“原样返回”。

如果程序从文件重定向输入，例如：

```bash
./a.out < input.txt > output.txt
```

就没有终端行缓冲和回显，程序会直接从文件读字节，直到文件末尾，然后退出。

---

## 4. 什么时候程序会停止？

当 `read` 返回 `0` 时，`while` 条件不成立，循环结束，程序退出。`fread` 返回 `0` 通常表示**到达文件末尾（EOF）**。

在交互式终端中，触发 EOF 的方式：

- **Linux / macOS / Unix**：按 `Ctrl + D`
  - 如果当前行是空的，按一次 `Ctrl+D` 就会发送 EOF。
  - 如果当前行还有字符，按 `Ctrl+D` 会先把当前行内容发送给程序，不发送换行；再按一次 `Ctrl+D` 才会发送 EOF。
- **Windows**：按 `Ctrl + Z`，然后按回车。

所以程序并不是“不会截断”，而是**只有遇到 EOF 才会停止**。只要没有 EOF，它就一直在 `while` 循环里逐字节读写。

---

## 6. 关于 `fread` / `fwrite` 和 `read` / `write`

顺便澄清：

- `fread` / `fwrite` 是 C 标准库函数，操作 `FILE*`，带用户空间缓冲。
- `read` / `write` 是 POSIX 系统调用，操作文件描述符 `int fd`，不带用户空间缓冲。
- `fread` / `fwrite` 内部最终可能会调用 `read` / `write` 来实际传输数据。

---

## 总结

你的程序不会“截断”，是因为：

1. `read` 每次只读 1 个字节，但外面有 `while` 循环，会一直读到 EOF。
2. `read` 不识别行、空格、换行，只按字节流处理。
3. 终端是行缓冲的，你按回车后整行才交给程序，程序再逐字节复制。
4. 终端本身有回显，程序也写到 `stdout`，所以看起来像“原样返回”。
5. 要结束程序，需要发送 EOF：Linux/macOS 用 `Ctrl+D`，Windows 用 `Ctrl+Z` 回车。

所以它不是“任由你输入”，而是“只要你不发 EOF，它就一直循环复制”。
